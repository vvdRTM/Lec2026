## 1. Зачем нужен JSON

Словарь удобен внутри Python-программы:

```python
device = {"name": "Датчик-1", "online": True, "note": None}
```

Но другой программе нужно передать данные в согласованном формате. Она может быть написана на другом языке и не понимать запись `True` или `None`.

**JSON**, JavaScript Object Notation, — текстовый формат представления структурированных данных. Несмотря на историческую связь названия с JavaScript, JSON используется независимо от языка программирования.

Те же сведения в JSON:

```json
{
  "name": "Датчик-1",
  "online": true,
  "note": null
}
```

JSON описывает данные, а не команды для выполнения. Для его обработки не требуется браузер, JavaScript или PHP. Python может самостоятельно прочитать JSON из локального файла или тела HTTP-ответа.

### 1.1. Три разных представления

| Где находятся данные | Что это |
|---|---|
| В файле `device.json` | Байты, которые читаются как JSON-текст в выбранной кодировке |
| В переменной `text` после чтения | Строка `str` с текстом JSON |
| В переменной `data` после разбора | Объект Python: например, словарь |

Не стоит называть любой из этих объектов просто «JSON», когда нужно понять тип. Уточняйте: JSON-файл, JSON-текст или разобранный словарь.

<a id="section-2"></a>

## 2. Типы JSON и соответствия Python

| JSON | Python после чтения | Пример JSON |
|---|---|---|
| Объект | `dict` | `{"theme": "dark"}` |
| Массив | `list` | `[18, 20, 22]` |
| Строка | `str` | `"готово"` |
| Целое число | `int` | `12` |
| Число с дробной частью или экспонентой | Обычно `float` | `2.5` |
| Логическое значение | `bool` | `true`, `false` |
| Отсутствующее значение | `None` | `null` |

Объект JSON состоит из пар «имя — значение». Имена полей — строки. Массив хранит последовательность значений в определённом порядке.

### 2.1. Вложенные данные

```json
{
  "room": "Аудитория 204",
  "readings": [18, 20, 22],
  "settings": {"unit": "C", "enabled": true}
}
```

После разбора `data["readings"]` будет списком, а `data["settings"]` — словарём. Для чтения единицы измерения понадобится `data["settings"]["unit"]`.

Корнем JSON может быть не только объект или массив, но и строка, число, логическое значение или `null`. Если ваша программа требует список записей, это отдельное ограничение программы.

<a id="section-3"></a>

## 3. Правила записи JSON

Основные отличия от привычной записи Python:

- Строки и имена полей заключаются в двойные кавычки.
- Логические значения пишутся `true` и `false` со строчной буквы.
- Отсутствующее значение обозначается `null`.
- После последнего поля или элемента не ставится лишняя запятая.
- В обычном JSON нет комментариев и произвольных Python-выражений.

Неверный JSON:

```text
{'name': 'Датчик-1', 'online': True}
```

Это похоже на представление словаря Python, но не соответствует правилам JSON.

### 3.1. Почему нельзя заменить все одинарные кавычки двойными

Кавычка может быть частью текста. Простой `replace()` не понимает структуру документа и может повредить данные. Для записи используют `json.dumps()` или `json.dump()`, для чтения — `loads()` или `load()`.

JSON нельзя разбирать через `eval()`: нам нужно прочитать данные, а не выполнить присланный текст как программу.

### 3.2. Строгий обмен данными

Стандарт JSON не предусматривает `NaN` и бесконечности. При записи чисел полезен аргумент `allow_nan=False`: он не даст случайно сформировать документ с такими значениями.

Не записывайте один и тот же ключ объекта несколько раз. Стандартный декодер Python обычно оставляет последнее значение повторного ключа, поэтому факт повтора может потеряться ещё до проверки полей.

<a id="section-4"></a>

## 4. Чтение JSON из строки: loads

Модуль `json` входит в стандартную библиотеку Python. Отдельная установка не нужна.

```python
import json

text = '{"name": "Датчик-1", "online": true, "note": null}'
data = json.loads(text)

print(type(text))      # <class 'str'>
print(type(data))      # <class 'dict'>
print(data["name"])    # Датчик-1
print(data["online"])  # True
print(data["note"])    # None
```

Сначала `text` содержит символы фигурных скобок, кавычек и названий полей. Вызов `loads()` разбирает эту запись и создаёт словарь. Только после этого можно обращаться к полям по ключам.

Буква `s` в имени `loads` помогает запомнить: источник — строка, string. Это не множественное число от «загрузки».

### 4.1. Типичная ошибка

Выражение `text["name"]` вызовет `TypeError`, потому что `text` — строка, и строковые индексы должны быть целыми. Разбор JSON не выполняется автоматически при обращении к ключу.

<a id="section-5"></a>

## 5. Получение JSON-текста: dumps

```python
import json

data = {"name": "Датчик-1", "online": True, "note": None}
text = json.dumps(data, ensure_ascii=False, indent=2, allow_nan=False)

print(type(text))  # <class 'str'>
print(text)
```

Результат:

```json
{
  "name": "Датчик-1",
  "online": true,
  "note": null
}
```

`ensure_ascii=False` оставляет кириллицу в читаемом виде. Значение по умолчанию может представить её последовательностями `\u...`; это тоже корректная запись того же текста.

`indent=2` задаёт отступы для удобного чтения. Эти пробелы не превращаются в поля и не меняют структуру данных.

### 5.1. Проверка обратного преобразования

```python
restored = json.loads(text)
assert restored == data
```

Для этого примера структура восстанавливается. Но JSON не сохраняет все возможные типы Python: кортеж записывается массивом и читается списком, множество без дополнительного преобразования не сериализуется.

Ключи JSON всегда строки. Словарь с целыми ключами после записи и чтения может получить строковые ключи. Если идентификатор нужен как число, удобнее хранить его значением поля записи, а не полагаться на сохранение типа ключа.

<a id="section-6"></a>

## 6. JSON-файлы: load и dump

Файл `demo_device.json` создаётся или перезаписывается в текущей рабочей папке:

```python
import json

data = {"name": "Датчик-1", "online": True}

with open("demo_device.json", "w", encoding="utf-8") as file:
    json.dump(data, file, ensure_ascii=False, indent=2, allow_nan=False)

with open("demo_device.json", "r", encoding="utf-8") as file:
    restored = json.load(file)

assert restored == data
```

| Действие | Строка | Открытый файловый объект |
|---|---|---|
| Получить объект Python | `json.loads(text)` | `json.load(file)` |
| Получить JSON | `json.dumps(data)` возвращает строку | `json.dump(data, file)` записывает в файл |

Кодировка задаётся в `open()`, а оформление JSON — в `dump()`. Это разные уровни работы с данными.

### 6.1. Один документ на файл

Если вызвать `dump()` несколько раз подряд в один файл без согласованного формата, могут получиться соседние JSON-документы, которые обычный `load()` целиком не прочитает.

Для учебной программы собирайте список записей в памяти и сохраняйте его одним вызовом. Форматы последовательностей документов, например JSON Lines, требуют отдельного договора о чтении.

<a id="section-7"></a>

## 7. Ошибки JSON и сохранность результатов

Неправильные кавычки, лишняя запятая или незакрытая скобка приводят к `json.JSONDecodeError`.

```python
import json

text = '{"online": true,}'

try:
    data = json.loads(text)
except json.JSONDecodeError as error:
    print(f"Неверный JSON: строка {error.lineno}, столбец {error.colno}")
```

Номер строки здесь относится к JSON-тексту, а не к номеру команды в `.py`-файле.

`JSONDecodeError` является подклассом `ValueError`. Если нужны отдельные сообщения об ошибке JSON и об ошибке структуры, сначала ставят обработчик `JSONDecodeError`, затем более общий `ValueError`.

### 7.1. Правильный порядок действий

Сначала прочитайте исходные данные, затем проверьте структуру, выполните вычисления и подготовьте текст результата. Только после этого открывайте выходной файл в режиме записи.

Сериализацию также можно выполнить заранее:

```python
text = json.dumps(data, ensure_ascii=False, indent=2, allow_nan=False)
# Выходной файл открывается после успешного формирования text.
```

Если в данных оказалось неподдерживаемое значение, ошибка возникнет до очистки прежнего файла. Это защищает от ошибок подготовки данных, но не гарантирует восстановления файла при сбое уже начавшейся записи. Схема временного файла и последующей замены обсуждалась в лекции №7.

<a id="section-8"></a>

## 8. Синтаксис JSON и структура программы

Документ `42` является корректным JSON. Документ `{"online": "да"}` тоже корректен по синтаксису. Но оба могут быть непригодны программе, ожидающей список записей с логическим состоянием.

Нужны два разных этапа:

1. **Разбор:** можно ли получить объект из JSON-текста?
2. **Проверка структуры:** соответствует ли полученный объект требованиям программы?

Общий пример записи:

```json
{
  "code": 7,
  "label": "Датчик окна",
  "online": false
}
```

Договоримся, что `code` — положительное целое число, `label` — непустой текст, `online` — логическое значение.

Последовательно проверяют тип корня, наличие обязательных полей, тип каждого значения и допустимость содержимого. Для списка дополнительно проверяют каждую запись и общие ограничения, например уникальность кода.

<a id="section-9"></a>

## 9. Строгие проверки чисел и bool

В Python есть особенность:

```python
print(isinstance(True, int))  # True
print(type(True) is int)     # False
print(type(True) is bool)    # True
```

`bool` связан с типом `int`, поэтому простой `isinstance(value, int)` допускает логические значения. Для идентификатора, который должен быть именно целым числом, используют строгую проверку.

```python
def validate_device(record):
    if not isinstance(record, dict):
        raise ValueError("Запись должна быть объектом")

    code = record.get("code")
    if type(code) is not int or code <= 0:
        raise ValueError("code должен быть положительным целым числом")

    label = record.get("label")
    if not isinstance(label, str) or not label.strip():
        raise ValueError("label должен содержать текст")

    if type(record.get("online")) is not bool:
        raise ValueError("online должен быть логическим значением")
```

Функция ничего не исправляет и не меняет запись. Если проверка пройдена, она завершается обычным образом; иначе вызывает `ValueError` с пояснением.

Не преобразуйте произвольный текст через `bool()` вместо проверки: `bool("false")` равно `True`, потому что строка непустая.

<a id="section-10"></a>

## 10. Отсутствующее поле, null и пустой текст

Эти состояния различаются:

| JSON-запись | Смысл |
|---|---|
| `{}` | Поле не передано |
| `{"note": null}` | Поле передано с отсутствующим значением |
| `{"note": ""}` | Передана пустая строка |
| `{"note": "Не проверено"}` | Передан конкретный текст |

Метод `get()` без запасного значения вернёт `None` и для отсутствующего поля, и для явно записанного `null`. Если эти случаи требуется различать, сначала проверяют `"note" in record`.

Отсутствующие сведения нельзя заменять выдуманными. Допустимая подпись «Не указано» относится к оформлению вывода и не должна превращаться в якобы полученное с сервера значение.

<a id="section-11"></a>

## 11. Проверка списка записей и уникальности

```python
def validate_devices(data):
    if not isinstance(data, list):
        raise ValueError("Ожидался список устройств")

    seen_codes = set()
    for index, record in enumerate(data, start=1):
        try:
            validate_device(record)
        except ValueError as error:
            raise ValueError(f"Запись {index}: {error}") from error

        code = record["code"]
        if code in seen_codes:
            raise ValueError(f"Повтор кода устройства: {code}")
        seen_codes.add(code)
```

`seen_codes` хранит уже встреченные коды. Первая запись с кодом 7 добавляет его в множество; следующая запись с тем же кодом обнаруживается проверкой принадлежности.

Пустой список здесь разрешён: он не содержит неправильных записей и повторов. Если программа требует хотя бы одну запись, это нужно проверить отдельно.

Дополнительные поля в данном примере допустимы. Но неизвестное поле не заменяет обязательное: `name` не считается автоматически тем же самым, что `label`.

<a id="section-12"></a>

## 12. Обработка проверенных данных

После проверки можно сосредоточиться на вычислении:

```python
def describe_devices(devices):
    online_count = 0
    for device in devices:
        if device["online"]:
            online_count += 1
    return f"Всего: {len(devices)}; в сети: {online_count}"


devices = [
    {"code": 7, "label": "Датчик окна", "online": True},
    {"code": 9, "label": "Датчик двери", "online": False},
]

validate_devices(devices)
print(describe_devices(devices))  # Всего: 2; в сети: 1
```

Сетевой запрос, чтение файла и `input()` не нужны внутри этой функции. Она получает готовый список и возвращает строку. Поэтому один и тот же алгоритм работает с данными из разных источников.

### 12.1. Общие приёмы анализа записей

Встречаются подсчёт по группам, выбор записей по условию и поиск максимального показателя. Для группировки обычно используется словарь: ключ группы связан с накопленным результатом.

Отдельно решайте, должны ли в результате присутствовать группы с нулевым показателем. Если группа добавляется только при успешном событии, группа без таких событий исчезнет. Чтобы сохранить её, сначала зарегистрируйте факт появления группы, затем обновляйте показатель по условию.

При поиске максимума проверьте пустой набор и возможность нескольких равных результатов. Один найденный максимум не означает, что соответствующая запись единственная.

<a id="section-13"></a>

## 13. Исходный порядок, типы идентификаторов и копии

При отборе записей обычным циклом сохраняется порядок обхода. Сортировать нужно только тогда, когда это требуется форматом результата.

Если идентификаторы получены как числа, сравнивайте их как числа. Строковое сравнение `"10" < "2"` не отражает числовой порядок.

Список отобранных словарей может содержать ссылки на исходные записи:

```python
selected = [device for device in devices if device["online"]]
```

Сам отбор не меняет записи. Но последующая команда `selected[0]["label"] = ...` изменит общий словарь. Если нужно независимо редактировать простые поля выбранных записей, используйте `device.copy()` при добавлении. Для вложенных изменяемых объектов требуется дополнительно продумать глубину копирования.

<a id="section-14"></a>

## 14. Проверки без интернета

Для проверки анализа используйте данные, которые сами задали:

```python
assert describe_devices([]) == "Всего: 0; в сети: 0"
assert describe_devices([
    {"code": 1, "label": "A", "online": False}
]) == "Всего: 1; в сети: 0"

try:
    validate_device({"code": True, "label": "A", "online": False})
except ValueError:
    pass
else:
    assert False, "Логическое значение принято за идентификатор"
```

Также проверяют неверный корень, пропущенное поле, повтор идентификатора, строку вместо `bool`, пустую подпись и неизменность исходных данных.

После записи и повторного чтения сравнивают структуры, а не пробелы JSON-текста. Документы с разными отступами могут представлять одинаковые данные.

Не выполняйте сетевые вызовы при импорте модуля с функциями. Интерактивный запуск помещайте под `if __name__ == "__main__":`.

<a id="section-15"></a>

## 15. API, клиент и сервер

**API**, application programming interface, — программный интерфейс: согласованный способ пользоваться возможностями другой части системы. Собственная функция тоже имеет интерфейс: имя, аргументы и результат.

**Веб-API** доступен через сеть. Клиент отправляет запрос по адресу сервиса, сервер обрабатывает запрос и возвращает ответ.

```text
Python-программа клиента
    отправляет HTTP-запрос
Сервер
    возвращает статус, заголовки и тело
Python-программа
    проверяет ответ и обрабатывает данные
```

HTTP и JSON решают разные задачи. HTTP организует обмен сообщениями, JSON описывает формат данных внутри сообщения. Сервер может вернуть HTML, изображение, пустое тело или JSON — это определяется конкретным ресурсом.

REST — архитектурный подход к построению систем и API. SOAP — отдельный протокол обмена, GraphQL — язык запросов и связанная модель API. Их не следует считать тремя форматами JSON. Для первого знакомства достаточно чтения ресурса обычным GET-запросом.

<a id="section-16"></a>

## 16. URL и выбор ресурса

Разберём условный адрес:

```text
https://api.example.com/devices?room=204&limit=10
```

| Часть | Назначение |
|---|---|
| `https` | Схема обращения с защищённым соединением |
| `api.example.com` | Имя узла сервера |
| `/devices` | Путь ресурса |
| `room=204&limit=10` | Параметры запроса |

Домен `example.com` используется в иллюстрации; это не адрес готового сервиса из курса.

Адрес является частью договора API. Профиль пользователя, список его записей и сведения о репозитории — разные ресурсы. По одному логину нельзя автоматически получить любой из них без выбора правильного пути.

Параметры запроса кодируют средствами библиотеки, а не ручным склеиванием произвольного пользовательского текста: пробелы, кириллица и специальные символы требуют корректного представления в URL.

<a id="section-17"></a>

## 17. HTTP-методы

| Метод | Обычное назначение |
|---|---|
| GET | Получить представление ресурса |
| POST | Передать данные для обработки, часто создать ресурс |
| PUT | Передать полное представление для создания или замены ресурса по адресу |
| PATCH | Передать частичное изменение |
| DELETE | Запросить удаление ресурса |

Точные действия задаёт документация сервиса. Метод сам по себе не гарантирует, что сервер реализовал ожидаемое поведение.

Для демонстраций чтения используем GET. Запросы изменения нельзя посылать к чужому сервису только ради проверки синтаксиса: они могут изменить реальные данные.

JSON чаще передаётся в теле POST, PUT или PATCH. Параметры URL и тело JSON — разные части запроса, даже если оба представляют пары «имя — значение».

<a id="section-18"></a>

## 18. Статус, заголовки и тело ответа

| Код | Обычный смысл |
|---|---|
| 200 | Успешный ответ |
| 201 | Ресурс создан |
| 204 | Успех без тела ответа |
| 301, 302 | Перенаправление |
| 400 | Неподходящий запрос |
| 401 | Требуется подходящая аутентификация |
| 403 | Доступ запрещён |
| 404 | Ресурс не найден |
| 429 | Превышено ограничение частоты |
| 500 | Внутренняя ошибка сервера |

Статус отвечает на вопрос о результате HTTP-операции. Он не доказывает, что тело содержит ожидаемые поля.

Заголовок `Content-Type` сообщает тип содержимого, например `application/json`. `Accept` в запросе сообщает, какое представление клиент готов принять. `User-Agent` описывает клиентскую программу.

Тело содержит сами данные. Ответ 204 может быть успешным и при этом не содержать JSON, который можно разобрать. Не вызывайте разбор тела автоматически для любого «успеха».

<a id="section-19"></a>

## 19. GET стандартными средствами Python

В стандартной библиотеке есть `urllib.request`. Следующий пример получает описание корня публичного GitHub API, а не профиль пользователя:

```python
import json
from urllib.request import Request, urlopen

request = Request(
    "https://api.github.com/",
    headers={"Accept": "application/json", "User-Agent": "python-course-demo"},
)

with urlopen(request, timeout=10) as response:
    text = response.read().decode("utf-8")
    data = json.loads(text)

if not isinstance(data, dict):
    raise ValueError("Ожидался объект JSON")

print(f"Получено полей: {len(data)}")
```

Порядок преобразований: HTTP-ответ, байты тела, строка UTF-8, объект Python. Не нужно путать каждый промежуточный объект со словарём.

Пример требует сети, а число полей не фиксируется в учебном тексте. При ошибке HTTP стандартный `urlopen()` может вызвать `HTTPError`, при проблеме соединения — `URLError`. Обработчики организуются отдельно от анализа данных. Назначение ресурса описано в [GitHub API Root](https://docs.github.com/en/rest/meta/meta#github-api-root), сетевые операции — в [документации urllib.request](https://docs.python.org/3/library/urllib.request.html).

<a id="section-20"></a>

## 20. Requests: сторонняя библиотека для HTTP

Requests упрощает распространённые действия клиента: GET-запросы, параметры, заголовки, JSON и сессии. Она не входит в стандартную библиотеку и устанавливается отдельно в окружение проекта.

```python
import requests

response = requests.get(
    "https://api.github.com/",
    headers={"Accept": "application/json", "User-Agent": "python-course-demo"},
    timeout=10,
)
response.raise_for_status()
data = response.json()
print(type(data))
```

`response` — объект ответа. `raise_for_status()` вызывает исключение при статусах 4xx и 5xx. `json()` разбирает тело, но не проверяет его соответствие нашей программе.

Библиотека является удобным вариантом поверх тех же принципов HTTP. Её использование не отменяет знание статусов и ошибок. Основные операции приведены в [официальном Quickstart Requests](https://requests.readthedocs.io/en/latest/user/quickstart/).

<a id="section-21"></a>

## 21. Объект Response

| Выражение | Что даёт |
|---|---|
| `response.status_code` | Числовой HTTP-статус |
| `response.headers` | Заголовки ответа |
| `response.content` | Содержимое как байты |
| `response.text` | Содержимое как текст |
| `response.json()` | Объект после разбора JSON |

`text` является свойством, а `json()` — вызовом метода, поэтому скобки у них различаются.

Метод `json()` может вызвать ошибку, если сервер вернул HTML или пустое тело. JSON с сообщением об ошибке также может успешно разбираться, хотя HTTP-операция не была успешной. Поэтому HTTP-статус и JSON проверяют отдельно.

Не используйте `if response:` как проверку точного статуса 200. У объекта ответа есть собственное правило истинности, связанное с отсутствием статусов ошибки. Для ожидаемого кода сравнивайте `status_code`, для обработки 4xx/5xx используйте `raise_for_status()`.

<a id="section-22"></a>

## 22. Параметры и заголовки Requests

Запрос к демонстрационному сервису, который возвращает сведения о полученном запросе:

```python
import requests

response = requests.get(
    "https://httpbin.org/get",
    params={"topic": "python", "limit": 3},
    headers={"Accept": "application/json"},
    timeout=10,
)
response.raise_for_status()
data = response.json()
print(data["args"])
```

`params` формирует параметры URL и выполняет необходимое кодирование. Сервис может представить полученные параметры строками, даже если в Python мы передали число 3.

Для отправки JSON Requests предоставляет аргумент `json=...`. Схема вызова выглядит как `requests.post(url, json=payload, timeout=10)`. Это уже операция передачи данных; выполняйте её только для предназначенного вам тестового или собственного сервиса.

`json=payload` и `data=payload` не равнозначны: второй вариант со словарём обычно используется для данных формы, а не для JSON-тела.

<a id="section-23"></a>

## 23. Таймауты и обработка ошибок Requests

Без явного таймаута программа может ждать ответа дольше, чем рассчитывает пользователь. `timeout=10` задаёт ограничения ожидания соединения и чтения, но не является общим десятисекундным сроком всей операции и программы.

Для раздельной настройки можно передать пару, например `timeout=(3, 10)`: ожидание соединения и ожидание данных. Подробности описаны в [документации Requests о таймаутах](https://requests.readthedocs.io/en/latest/user/advanced/#timeouts).

```python
import requests

try:
    response = requests.get("https://api.github.com/", timeout=(3, 10))
    response.raise_for_status()
    data = response.json()
except requests.exceptions.JSONDecodeError:
    print("Ответ не содержит корректный JSON")
except requests.exceptions.Timeout:
    print("Превышено время ожидания")
except requests.exceptions.HTTPError as error:
    print(f"Ошибка HTTP: {error.response.status_code}")
except requests.exceptions.RequestException as error:
    print(f"Не удалось выполнить запрос: {error}")
else:
    if not isinstance(data, dict):
        print("Неожиданная структура ответа")
    else:
        print("Получен объект JSON")
```

Конкретные типы ошибок стоят раньше общего `RequestException`. Подключённая библиотека может использовать собственный класс ошибки JSON, поэтому для Requests обрабатываем её документированный тип.

При 429 не запускайте немедленный бесконечный повтор. Сервер ограничивает частоту; изучите ответ и правила сервиса. Для учебного примера достаточно одного управляемого запроса.

Проверка сертификата HTTPS обычно включена. Не отключайте её через `verify=False` как обычный способ «починить запрос».

<a id="section-24"></a>

## 24. Сессии и повторное использование настроек

```python
import requests

with requests.Session() as session:
    session.headers.update({"User-Agent": "python-course-demo"})
    response = session.get("https://api.github.com/", timeout=10)
    response.raise_for_status()
    data = response.json()
```

Сессия позволяет хранить общие настройки и cookies, а также повторно использовать соединения, когда это возможно. Это полезно при нескольких обращениях к одному сервису. Контекст закрывает сессию после использования. Эти возможности описаны в [Advanced Usage Requests](https://requests.readthedocs.io/en/latest/user/advanced/).

Автоматические повторы не следует добавлять без анализа операции. Повтор чтения и повтор создания заказа имеют разные последствия. На первом этапе важнее правильно отличить полученный ответ от отсутствия соединения.

<a id="section-25"></a>

## 25. Один алгоритм для локальных и сетевых данных

```python
import json


def describe_service(data):
    if not isinstance(data, dict):
        raise ValueError("Ожидался объект")
    name = data.get("name")
    if not isinstance(name, str) or not name.strip():
        raise ValueError("Отсутствует название сервиса")
    if type(data.get("available")) is not bool:
        raise ValueError("available должно быть логическим")
    state = "доступен" if data["available"] else "недоступен"
    return f"{name}: {state}"


sample = '{"name": "Учебный сервис", "available": true}'
data = json.loads(sample)
print(describe_service(data))
# Учебный сервис: доступен
```

Сетевая функция могла бы вернуть объект такой же структуры. `describe_service()` не обязана знать источник данных: она проверяет свой договор и формирует строку.

Для полноценного режима без сети храните пример в локальном JSON-файле. В выводе или отчёте укажите, что использованы учебные данные. Такой режим проверяет обработку, но не доказывает доступность реального сервера.

### 25.1. Общая организация программы

Разделите функции загрузки, проверки, анализа и сохранения. Проверяйте вычислительные функции локально, а сетевую часть — отдельным коротким запуском. Так изменение внешнего API не будет выглядеть как ошибка каждого теста алгоритма.

## 26. Модуль, пакет, библиотека и окружение

**Модуль** — импортируемая единица, часто `.py`-файл. **Пакет** организует модули. **Библиотека** — набор средств для задач приложения. **Фреймворк** дополнительно задаёт организацию работы и вызывает ваши функции по своим правилам, например при HTTP-запросе.

Стандартные `json`, `pathlib`, `urllib`, `csv` и `unittest` не нужно устанавливать через pip. Requests, NumPy и другие сторонние инструменты устанавливаются в выбранное окружение.

```text
python -m venv .venv
```

## 28. NumPy: численные массивы

NumPy предоставляет массивы с общей формой и типом элементов. Она используется для численных вычислений. В [руководстве NumPy для начинающих](https://numpy.org/doc/stable/user/absolute_beginners.html) рассматриваются массивы и базовые операции.

Установка: `python -m pip install numpy` в выбранном окружении.

```python
import numpy as np

values = np.array([18, 20, 22])
corrected = values + 1

print(corrected.tolist())  # [19, 21, 23]
print(float(values.mean()))  # 20.0
```

`np` — принятое краткое имя модуля. Сложение с числом применяется поэлементно. Обычный список Python не поддерживает такую же операцию `list + 1`.

### 28.1. Таблица в NumPy

```python
table = np.array([[18, 20], [22, 24]])
print(table.shape)              # (2, 2)
print(table.mean(axis=0).tolist())  # [20.0, 22.0]
```

`shape` описывает размеры. `axis=0` в этом примере означает вычисление среднего по строкам для каждого столбца. Получается один показатель на столбец.

При чтении кода уточняйте тип: операции массива и списка могут выглядеть одинаково, но иметь разный смысл. Для численных массивов также заранее учитывают тип и диапазон значений.

## 29. pandas: таблицы с именованными столбцами

Главная структура pandas — `DataFrame`, таблица с метками строк и столбцов. Сведения о ней приведены в [вводном руководстве pandas](https://pandas.pydata.org/docs/getting_started/intro_tutorials/01_table_oriented.html).

Установка: `python -m pip install pandas`.

```python
import pandas as pd

frame = pd.DataFrame({
    "sensor": ["A", "B", "C"],
    "temperature": [18, 20, 22],
})

print(frame["temperature"].mean())  # 20.0
warm = frame[frame["temperature"] >= 20]
print(warm["sensor"].tolist())  # ['B', 'C']
```

`frame["temperature"]` выбирает столбец. Сравнение создаёт логическую маску: для каждой строки определяется, подходит ли значение. Внешние квадратные скобки оставляют строки, где маска истинна.

Библиотека умеет читать CSV и другие форматы. Для некоторых форматов нужны дополнительные движки, например пакет для чтения определённых Excel-файлов. Наличие pandas само по себе не гарантирует поддержку любого файла без дополнительных компонентов.

## 31. SciPy: готовые численные методы

SciPy дополняет массивы NumPy средствами научных вычислений. Например, можно искать корни уравнений и оптимальные параметры. Направления описаны в [руководстве SciPy по оптимизации](https://docs.scipy.org/doc/scipy/tutorial/optimize.html).

Установка: `python -m pip install scipy`.

```python
from scipy.optimize import root_scalar


def equation(x):
    return x * x - 2


result = root_scalar(equation, bracket=[1, 2], method="bisect")
print(result.converged)      # True
print(round(result.root, 3)) # 1.414
```

Функция получает математическое правило и интервал поиска. На границах 1 и 2 значения выражения имеют разные знаки. Метод деления пополам уточняет положение корня.

Численный ответ приближённый. Нужно учитывать условия применимости метода и проверять признак успешного завершения, а не только печатать число.

## 32. Веб-разработка: Flask, FastAPI и Django

В предыдущих сетевых примерах Python был клиентом. В веб-приложении наша программа может быть серверной частью, принимающей запросы.

### 32.1. Flask: небольшой серверный пример

Установка: `python -m pip install flask`. Сохраните `demo_web.py`:

```python
from flask import Flask

app = Flask(__name__)


@app.get("/status")
def status():
    return {"service": "demo", "available": True}
```

Запуск в терминале:

```text
python -m flask --app demo_web run
```

Откройте `http://127.0.0.1:5000/status`. Строка `@app.get(...)` — декоратор, связывающий путь и метод GET с функцией. Фреймворк вызывает её и превращает словарь в JSON-ответ. Для остановки учебного сервера используется Ctrl+C.

Здесь сервер разработки нужен для локального знакомства. Публикация приложения требует отдельной настройки. Основная схема приведена в [Flask Quickstart](https://flask.palletsprojects.com/en/stable/quickstart/).

### 32.2. FastAPI: API и описание типов

Установка: `python -m pip install "fastapi[standard]"`. Сохраните `demo_api.py`:

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/status")
def status():
    return {"service": "demo", "available": True}
```

Запуск:

```text
python -m fastapi dev demo_api.py
```

При стандартной конфигурации пример доступен на `http://127.0.0.1:8000/status`, описание API — на `/docs`. Фреймворк поддерживает описание параметров и данных через типы. Подробности: [First Steps FastAPI](https://fastapi.tiangolo.com/tutorial/first-steps/).

### 32.3. Django: более полный набор средств

Django включает инструменты маршрутизации, шаблонов, работы с моделями данных, аутентификации и администрирования. Он подходит, когда требуется организованное веб-приложение с несколькими связанными подсистемами. Набор возможностей описан в [официальном обзоре Django](https://www.djangoproject.com/start/overview/).

Flask, FastAPI и Django не являются универсальным рейтингом «хуже — лучше». Выбор зависит от проекта и команды. Асинхронность тоже не делает любую программу автоматически быстрее.

## 33. Машинное обучение: scikit-learn и нейросетевые инструменты

Машинное обучение строит модель по примерам. Для первого знакомства достаточно различать обучение и применение модели.

Установка: `python -m pip install scikit-learn`.

```python
from sklearn.linear_model import LinearRegression

inputs = [[1], [2], [3]]
outputs = [2, 4, 6]

model = LinearRegression()
model.fit(inputs, outputs)
prediction = model.predict([[4]])
print(round(float(prediction[0]), 2))  # 8.0
```

`fit()` подбирает параметры по данным, `predict()` применяет обученную модель. Вход `[[1], [2], [3]]` содержит три примера с одним признаком в каждом. Искусственные числа показывают интерфейс, но не доказывают полезность модели для реальной задачи.

Качество оценивают на данных, не использованных для обучения. Основные роли методов описаны в [Getting Started scikit-learn](https://scikit-learn.org/stable/getting_started.html).

### 33.1. PyTorch, TensorFlow и Keras

PyTorch и TensorFlow предоставляют средства для тензоров и обучения нейронных сетей. Keras предлагает высокоуровневый интерфейс построения моделей; конкретный вычислительный backend выбирается согласно его документации.

Пример операции PyTorch после отдельной установки подходящей сборки:

```python
import torch

values = torch.tensor([1.0, 2.0, 3.0])
print((values * 2).tolist())  # [2.0, 4.0, 6.0]
```

Это операция над тензором, а не обучение нейросети. Средства тензоров рассматриваются в [руководстве PyTorch](https://docs.pytorch.org/tutorials/beginner/basics/tensorqs_tutorial.html). Сборку и аппаратные требования проверяют перед установкой.

## 37. Базы данных

JSON удобен для обмена и небольших файлов. Когда нужны запросы, связанные таблицы, ограничения и транзакции, применяют базы данных.

Стандартный модуль `sqlite3` позволяет работать с SQLite без отдельного серверного процесса. Следующий пример использует базу только в памяти:

```python
import sqlite3

connection = sqlite3.connect(":memory:")
try:
    with connection:
        connection.execute("CREATE TABLE devices (name TEXT, online INTEGER)")
        connection.execute(
            "INSERT INTO devices VALUES (?, ?)",
            ("Датчик-1", 1),
        )
    rows = connection.execute("SELECT name FROM devices").fetchall()
    print(rows)  # [('Датчик-1',)]
finally:
    connection.close()
```

Знаки `?` — параметры SQL-запроса. Значения передаются отдельно, а не вставляются строковой склейкой. Контекст соединения управляет транзакцией, но сам по себе не закрывает соединение — поэтому закрытие выполнено в `finally`.

Основные правила приведены в [документации sqlite3](https://docs.python.org/3/library/sqlite3.html).

SQLAlchemy предоставляет средства описания SQL и работы через ORM. Psycopg используется для PostgreSQL. Библиотека доступа не заменяет саму СУБД и настройку соединения.

## 38. pytest и автоматические проверки

`unittest` входит в стандартную библиотеку. pytest устанавливается отдельно и позволяет начать с обычных функций и `assert`.

Установка: `python -m pip install pytest`. Файл `test_demo.py`:

```python
import json


def test_json_boolean():
    data = json.loads('{"available": false}')
    assert data["available"] is False


def test_json_round_trip():
    original = {"label": "Датчик", "available": True}
    text = json.dumps(original, ensure_ascii=False)
    assert json.loads(text) == original
```

Запуск:

```text
python -m pytest -q test_demo.py
```

pytest обнаруживает функции `test_...` и выполняет их. Подробное начало работы: [Get Started pytest](https://docs.pytest.org/en/stable/getting-started.html).

Для сети нужны отдельные проверки. Постоянная доступность чужого сервера не должна быть условием прохождения всех локальных тестов.

## 39. Как выбирать инструменты и находить ошибки

Начните с задачи, а не с количества известных названий. Для локального JSON достаточно `json`; для HTTP без дополнительных зависимостей — `urllib`; для удобного клиента — Requests; для таблиц с именованными столбцами — pandas.

| Симптом | Что проверить |
|---|---|
| `ModuleNotFoundError` | Окружение, установку и имя импорта |
| Локальный `requests.py` мешает импорту | Имя собственного файла |
| `JSONDecodeError` | Реальное содержимое, кавычки, пустое тело |
| Поле не читается по ключу | Тип корня и этап `loads()` |
| `completed="false"` считается истинным | Строгий тип bool вместо истинности строки |
| HTTP 200, но нет нужных данных | Проверку структуры ответа |
| Запрос долго не возвращается | Явный таймаут и доступность сети |
| Отобранные записи меняют исходник | Общие ссылки на словари |
| Тесты требуют интернет при импорте | Разделение загрузки и анализа |
| После неверного входа исчез результат | Момент открытия файла в режиме `w` |

Сначала добейтесь правильности небольшого примера и понятного договора данных. Затем добавляйте сеть, графики или дополнительные пакеты по мере необходимости.

## 40. Вопросы с разбором

### 40.1. Является ли словарь в памяти JSON-текстом?

Нет. Словарь является объектом Python. Для получения JSON-строки используют сериализацию.

### 40.2. Чем load отличается от loads?

`load()` получает файловый объект, `loads()` разбирает текст. Результат определяется содержимым JSON.

### 40.3. Сохраняет ли str(data) корректный JSON?

Нет. Представление Python может содержать одинарные кавычки, `True` и `None`. Используйте модуль `json`.

### 40.4. Почему JSON может разобраться, но программа всё равно не должна его принимать?

Корень, поля и типы могут нарушать договор приложения. Синтаксис и структура проверяются отдельно.

### 40.5. Почему True нельзя принимать как целочисленный идентификатор?

Для строгого числового кода логическое значение не подходит, хотя `isinstance(True, int)` истинно. Проверяют `type(value) is int`.

### 40.6. Что означает null?

Отсутствующее значение. При стандартном чтении Python получает `None`, а не строку `"null"`.

### 40.7. Доказывает ли статус 200 правильность JSON?

Нет. Тело может иметь другой формат или не содержать обязательных полей.

### 40.8. Чем response.text отличается от response.json()?

Первое даёт текст, второе разбирает JSON и возвращает объект Python. Успех разбора не заменяет проверку структуры.

### 40.9. Входит ли Requests в стандартную библиотеку?

Нет. Это сторонний пакет. Стандартный вариант HTTP-клиента рассматривается через `urllib.request`.

### 40.10. Ограничивает ли timeout=10 время всей программы десятью секундами?

Нет. Это настройки ожидания сетевых операций, а не общий таймер приложения.

### 40.11. Зачем локальный JSON, если данные должны приходить из сети?

Он позволяет независимо проверять разбор и алгоритм на воспроизводимых данных. Доступность сети проверяется отдельно.

### 40.12. Чем NumPy-массив отличается от списка в выражении values + 1?

Для массива такое сложение применяется поэлементно. У обычного списка сложение с целым числом недопустимо.

### 40.13. Требуется ли pandas для чтения любого JSON?

Нет. Для обычного чтения достаточно стандартного `json`. pandas нужен, когда удобна табличная обработка.

### 40.14. Является ли пример с tensor обучением нейросети?

Нет. Он показывает только хранение и арифметику тензоров.

### 40.15. Почему нельзя учить сразу все библиотеки из таблицы?

Они решают разные задачи и опираются на разные понятия. Для начала достаточно выбрать направление и освоить один небольшой законченный сценарий.

## 43. HTTPX, ограниченные повторы и фоновые задачи

В этом дополнении каждый фрагмент — отдельный пример. Имена пакетов указаны для установки через `python -m pip install ИМЯ` в окружение из раздела 26. Устанавливайте только то, что нужно для выбранного примера. Для Pydantic ниже используется API версии 2.

### 43.1. HTTPX: второй вариант HTTP-клиента

[HTTPX](https://www.python-httpx.org/) — самостоятельный HTTP-клиент, а не надстройка над Requests. Пакет: `httpx`. Обычный `Client` ждёт ответ как привычный синхронный вызов. `AsyncClient` предназначен для кода с `async` и `await`: пока один запрос ждёт данные, цикл событий может выполнять другие задачи.

Для знакомства достаточно синхронного режима. Следующий пример использует учебный ответ прямо в памяти: `MockTransport` передаёт запрос функции вместо обращения к реальному серверу.

```python
import httpx

def demo_server(request):
    assert request.method == "GET"
    assert request.url.path == "/status"
    return httpx.Response(200, json={"online": True})

with httpx.Client(transport=httpx.MockTransport(demo_server), timeout=5) as client:
    response = client.get("https://demo.example/status")
    response.raise_for_status()
    assert response.json()["online"] is True
```

Без учебного транспорта клиент обратился бы по сети. Правила из основной части остаются: проверить HTTP-статус, разобрать тело, проверить поля и типы.

### 43.2. Retrying: повтор с ограничением

[Retrying](https://pypi.org/project/retrying/) добавляет повторные попытки вызова. Пакет: `retrying`. Ниже первый вызов имитирует временную ошибку, второй возвращает значение. Попыток всего не более трёх, пауза задаётся в миллисекундах.

```python
from retrying import retry

attempts = iter([False, True])

@retry(
    stop_max_attempt_number=3,
    wait_fixed=100,
    retry_on_exception=lambda error: isinstance(error, TimeoutError),
)
def read_status():
    if not next(attempts):
        raise TimeoutError("Временный сбой")
    return {"online": True}

assert read_status() == {"online": True}
```

Здесь повторяется только ожидаемая временная ошибка. Повтор не исправит неправильный формат данных. Для операций с побочными эффектами, например создания заказа, нужно заранее исключить дублирование; повторять их вслепую нельзя.

### 43.3. Celery и Dramatiq: работа за пределами запроса

Если создание отчёта долгое, веб-приложение может поставить задачу в очередь и вернуть её номер. **Брокер** передаёт сообщение, **worker** выполняет работу отдельно. Клиент запрашивает состояние задачи позже. [Celery](https://docs.celeryq.dev/en/stable/getting-started/introduction.html) и [Dramatiq](https://dramatiq.io/guide.html) реализуют такой подход. Пакеты: `celery` и `dramatiq`.

В Celery декоратор `@app.task` регистрирует задачу. Здесь `apply()` выполняет её локально, чтобы проверить вычисление без брокера:

```python
from celery import Celery

app = Celery("demo")

@app.task
def total(values):
    return sum(values)

assert total.apply(args=([18, 20, 22],), throw=True).get() == 60
```

В Dramatiq зарегистрированную функцию называют **actor**. Учебный `StubBroker` не требует отдельного сервера, а прямой вызов проверяет только функцию:

```python
import dramatiq
from dramatiq.brokers.stub import StubBroker

dramatiq.set_broker(StubBroker())

@dramatiq.actor
def total(values):
    return sum(values)

assert total([18, 20, 22]) == 60
```

В рабочем приложении `total.delay(...)` в Celery и `total.send(...)` в Dramatiq отправляют сообщение. Для фонового выполнения нужны настроенные брокер и worker; локальные вызовы выше очередь и доставку не проверяют.

## 44. Русская морфология: pymorphy2, pymorphy3 и pymystem3

Метод `lower()` меняет регистр, но не приводит «датчиками» и «датчик» к общей форме. **Лемматизация** находит словарную форму слова, что полезно, например, для поиска по заметкам.

[pymorphy2](https://pymorphy2.readthedocs.io/en/stable/) упомянут в подборке. Для нового примера используем [pymorphy3](https://pypi.org/project/pymorphy3/) — продолжение проекта, с сохранением знакомого интерфейса `MorphAnalyzer`. У старого пакета проверяйте совместимость с вашей версией Python.

```python
from pymorphy3 import MorphAnalyzer

morph = MorphAnalyzer()
result = morph.parse("датчиками")[0]
print(result.normal_form)  # датчик
print(result.tag)         # грамматические признаки
```

`parse()` даёт варианты анализа. Выбор первого варианта удобен для демонстрации, но не гарантирует верного разбора в контексте: слово «стали» может относиться к глаголу «стать» или к существительному «сталь».

[pymystem3](https://pypi.org/project/pymystem3/) — Python-обёртка над отдельным анализатором Mystem. Для запуска нужен совместимый исполняемый файл Mystem; обёртка может пытаться установить его автоматически, если он не найден. Поэтому пример выполняют после подготовки этого компонента, а не рассчитывают только на установку пакета:

```python
from pymystem3 import Mystem

analyzer = Mystem()
words = analyzer.lemmatize("Датчики работают.")
print([word for word in words if word.strip().isalpha()])
```

В результате анализатор может возвращать также пробелы и знаки препинания, поэтому для этого вывода оставляем только буквенные элементы.

## 45. Схема данных, даты и сообщения программы

### 45.1. Pydantic: проверка JSON по описанию полей

[Pydantic](https://pydantic.dev/docs/validation/latest/concepts/strict_mode/) подходит, когда ручные проверки полей начинают повторяться. Пакет: `pydantic`, API версии 2. В модели описываем допустимые поля; строгий режим здесь нужен, чтобы строка `"7"` или логическое значение не принимались за целый код.

```python
from pydantic import BaseModel, ConfigDict, Field, ValidationError

class Device(BaseModel):
    model_config = ConfigDict(strict=True)
    code: int = Field(gt=0)
    online: bool

device = Device.model_validate_json('{"code": 7, "online": false}')
assert device.model_dump() == {"code": 7, "online": False}

try:
    Device.model_validate_json('{"code": true, "online": false}')
except ValidationError:
    print("Логический код отклонён")
else:
    raise AssertionError("Ожидалась ошибка проверки")
```

`model_validate_json()` разбирает текст и проверяет поля, `model_dump()` возвращает обычный словарь. Схема одной записи не проверяет уникальность кодов во всём списке: это остаётся отдельным правилом программы.

### 45.2. dateparser: разбор дат из текста

[dateparser](https://dateparser.readthedocs.io/en/latest/index.html) разбирает даты в разных формах. Пакет: `dateparser`. Относительное слово «вчера» зависит от точки отсчёта, поэтому в примере она задана явно.

```python
from datetime import datetime
import dateparser

value = dateparser.parse(
    "вчера",
    languages=["ru"],
    settings={"RELATIVE_BASE": datetime(2026, 11, 13, 12, 0)},
)
assert value is not None
print(value.date().isoformat())  # 2026-11-12
```

Если строка не распознана, результатом может быть `None`. Для формата, который всегда задан точно, например `2026-11-13`, часто достаточно стандартного `date.fromisoformat()`. При двусмысленной записи вроде `03/04/2026` заранее согласуйте порядок дня и месяца.

### 45.3. Rich и Loguru: оформление вывода и журнал событий

[Rich](https://rich.readthedocs.io/en/stable/introduction.html) помогает показать данные в терминале. Пакет: `rich`. Например, вместо списка словарей можно напечатать таблицу:

```python
from rich.console import Console
from rich.table import Table

table = Table(title="Датчики")
table.add_column("Код")
table.add_column("Состояние")
table.add_row("7", "В сети")
Console().print(table)
```

[Loguru](https://loguru.readthedocs.io/en/stable/) записывает события программы. Пакет: `loguru`. В отличие от таблицы для пользователя, журнал нужен для диагностики. Уровень `INFO` сообщает об обычной работе, `WARNING` — о ситуации, требующей внимания.

```python
from loguru import logger

logger.info("Прочитано записей: {}", 2)
logger.warning("Устройство {} не в сети", 9)
```

Для журналирования без сторонних зависимостей подходит стандартный `logging`. Ни в журнал, ни в диагностический вывод не следует записывать пароли и токены доступа.

## 46. Диагностика: py-spy и Pympler

**Профилирование** — измерение поведения выполняемой программы. Начните с вопроса: медленно ли работает вычисление или растёт память? Для этих ситуаций нужны разные измерения.

[py-spy](https://github.com/benfred/py-spy#usage) периодически снимает стек вызовов: фиксирует, в каких функциях находится программа. Пакет: `py-spy`; запускается командой, а не импортом. Для своего скрипта `demo.py` можно собрать отчёт в отдельный файл:

```text
py-spy record -o demo-profile.svg -- python demo.py
```

Отчёт помогает найти функции, часто попадающие в выборку. Он не доказывает, что каждая такая функция ошибочна. Доступ к измерениям зависит от платформы и разрешений; для знакомства запускайте собственный процесс.

[Pympler](https://pympler.readthedocs.io/en/latest/) исследует объекты Python и их память. Пакет: `pympler`.

```python
from pympler import asizeof

small = [{"code": 1}]
large = [{"code": i} for i in range(1000)]
print(asizeof.asizeof(small))
print(asizeof.asizeof(large))
```

Здесь сравниваются оценки размера структур с учётом вложенных объектов. Точные числа зависят от версии Python и платформы; это не измерение всей памяти процесса. Чтобы исследовать рост, сравнивают несколько измерений в одинаковых условиях.

## 47. Responses, Freezegun, Faker и factory_boy

Эти инструменты дополняют `pytest` и `unittest`. Они помогают контролировать внешние условия и создавать данные, а запуск проверок всё равно организует выбранный тестовый инструмент.

### 47.1. Responses: управляемый ответ для Requests

[Responses](https://github.com/getsentry/responses#basics) подменяет обращения библиотеки Requests внутри теста. Пакеты для примера: `responses` и `requests`. Тест не зависит от DNS, подключения или настоящего сайта:

```python
import requests
import responses

with responses.RequestsMock() as mocked:
    mocked.get(
        "https://demo.example/status",
        json={"online": False},
        status=200,
    )
    response = requests.get("https://demo.example/status", timeout=5)
    assert response.status_code == 200
    assert response.json()["online"] is False
```

Заменив статус на 404 или передав неправильное тело, можно отдельно проверить обработчики. Для HTTPX в разделе 43 использовался его собственный тестовый транспорт: Responses предназначен именно для Requests.

### 47.2. Freezegun: повторяемые проверки времени

[Freezegun](https://pypi.org/project/freezegun/) временно подменяет показания часов, которые видит Python-код внутри теста. Пакет: `freezegun`.

```python
from datetime import date
from freezegun import freeze_time

with freeze_time("2026-11-13 12:00:00"):
    assert date.today().isoformat() == "2026-11-13"
```

Часы операционной системы не меняются. Так можно проверить правило, зависящее от даты, без ожидания нужного дня. Если функция уже принимает дату аргументом, часто проще передать её явно.

### 47.3. Faker и factory_boy: данные и целые объекты

[Faker](https://faker.readthedocs.io/en/master/) создаёт синтетические значения. Пакет: `faker`. Для тестов можно зафиксировать начальное состояние генератора. При смене версии пакета сами строки могут отличаться, поэтому в этом примере проверяем свойство, а не конкретное имя:

```python
from faker import Faker

fake = Faker("ru_RU")
fake.seed_instance(8)
assert fake.name().strip()
```

[factory_boy](https://factoryboy.readthedocs.io/en/stable/) описывает, как собирать целые тестовые объекты с умолчаниями и настраиваемыми полями. Пакет: `factory_boy`, импорт: `factory`. Фабрика не является фикстурой pytest, хотя фикстура может использовать её внутри.

```python
from dataclasses import dataclass
import factory

@dataclass
class Device:
    code: int
    online: bool

class DeviceFactory(factory.Factory):
    class Meta:
        model = Device

    code = factory.Sequence(lambda number: number + 1)
    online = True

offline = DeviceFactory(online=False)
assert offline.code == 1
assert offline.online is False
```

Фабрика заполняет код автоматически, а статус в конкретном тесте мы переопределяем. Faker можно использовать для отдельных текстовых полей такой фабрики.

## 48. Funcy, tqdm и Black: повседневные инструменты

### 48.1. Funcy: преобразование коллекций

[Funcy](https://funcy.readthedocs.io/en/stable/overview.html) содержит готовые операции над коллекциями. Пакет: `funcy`. Пример: преобразовать значения словаря, сохранив ключи.

```python
from funcy import walk_values

readings = {"A": 18, "B": 20}
corrected = walk_values(lambda value: value + 1, readings)
assert corrected == {"A": 19, "B": 21}
```

То же действие можно записать обычным словарным включением `{key: value + 1 for key, value in readings.items()}`. Для одной простой операции сторонний пакет не обязателен.

### 48.2. tqdm: прогресс цикла

[tqdm](https://tqdm.github.io/) показывает ход обработки. Пакет: `tqdm`. Он оборачивает последовательность, а само вычисление остаётся в вашем коде:

```python
from tqdm import tqdm

total = 0
for value in tqdm([18, 20, 22], desc="Измерения", unit="запись"):
    total += value

assert total == 60
```

На коротком списке полоска исчезает или завершается почти сразу. Польза заметна при длительном проходе по файлам или записям. Индикатор не ускоряет алгоритм и не подтверждает правильность результата.

### 48.3. Black: единообразное форматирование

[Black](https://black.readthedocs.io/en/stable/usage_and_configuration/the_basics.html) — автоформаттер, пакет `black`. Он меняет оформление Python-кода по своим правилам; корректность алгоритма проверяется отдельно. Для первого знакомства посмотрите предлагаемые изменения без записи в исходник:

```text
python -m black --check --diff demo.py
```

`--check` сообщает, требуется ли форматирование, `--diff` показывает разницу. Если изменение нужно, команда с `--check` может завершиться ненулевым кодом — это ожидаемый результат проверки. Обычный запуск без этих параметров форматирует файл на месте.

**Самопроверка.** Чем проверить структуру ответа, подменить сетевой ответ в тесте и понять, почему процесс расходует всё больше памяти? Для этих задач подходят соответственно Pydantic, Responses или тестовый транспорт HTTPX, и Pympler.
