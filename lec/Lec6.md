# Лекция 6. Python: функции и коллекции

В предыдущей лекции мы обрабатывали строки и списки: выбирали элементы, создавали новые последовательности и сохраняли исходные данные. Теперь научимся объединять действия в именованные функции и выбирать структуры данных под смысл информации.

**Функция** описывает действие, которое можно вызвать с разными аргументами. **Коллекция** объединяет несколько значений. Список уже знаком; к нему добавятся кортеж, словарь и множество. Эти структуры решают разные задачи: последовательность шагов, фиксированная пара, запись с именованными полями и набор уникальных значений.

В примерах будем использовать подписи сообщений, настройки интерфейса, координаты и состояния устройств. Сначала разберём каждую конструкцию отдельно, затем объединим функции и коллекции в небольшой программе формирования сообщения о состоянии устройства.

### Как работать с материалом

Перед этой лекцией нужно понимать присваивание, условие `if`, цикл `for`, строки и списки. Все остальные понятия вводятся по мере необходимости.

Фрагменты кода изучайте по шагам. Сначала найдите определения функций, затем место вызова. Назовите передаваемые данные, проследите выполнение тела и определите, куда попадёт результат. Если рядом показаны два варианта с одинаковыми именами функций, запускайте их отдельно: новое определение с тем же именем заменяет прежнюю связь имени с функцией.

В разделах о коллекциях каждый раз задавайте три вопроса: что хранится, как найти нужное значение и можно ли изменить контейнер. Так легче увидеть смысл структуры за её синтаксисом.

Основной материал — определения и вызовы функций, `return`, локальные имена, кортежи, словари и множества. Аннотации, изменяемые значения по умолчанию и хешируемость можно изучать вторым проходом после базовых примеров.

### Что нужно освоить

После изучения материала студент должен:

- определять функцию через `def` и вызывать её;
- различать параметр и аргумент;
- передавать позиционные и именованные аргументы;
- отличать возвращаемое значение от вывода на экран;
- понимать локальные имена и изменение переданного объекта;
- использовать параметры по умолчанию без общего изменяемого значения;
- возвращать несколько значений и распаковывать кортеж;
- выбирать между `list`, `tuple`, `dict` и `set`;
- читать и изменять словарь, проверять ключи, использовать `get()` и `items()`;
- выполнять операции над множествами;
- объяснять ограничения ключей словаря и элементов множества;
- отделять вычисление результата от взаимодействия с пользователем;
- проверять функции на заранее рассчитанных примерах.

## 1. Зачем выделять функцию

Представим, что программа несколько раз формирует подпись пользователя:

```python
first_label = "Пользователь: " + "Мира"
second_label = "Пользователь: " + "Олег"
print(first_label)
print(second_label)
```

Повторяется правило, а меняется только имя. Его можно выразить функцией:

```python
def make_user_label(name):
    return f"Пользователь: {name}"


print(make_user_label("Мира"))
print(make_user_label("Олег"))
```

Теперь изменение шаблона подписи выполняется в одном месте. Имя `make_user_label` сообщает читателю, что делает этот участок программы.

Функции полезны и без многократного вызова. Большую программу легче читать, если в ней видны отдельные действия с понятными именами: получить настройки, сформировать сообщение, показать результат.

До этого мы уже вызывали готовые функции: `len(text)`, `int(value)`, `print(message)`. Теперь создаём собственные функции с такими же общими принципами: у вызова есть имя, ему можно передать данные и получить результат.

Функцию удобно представить как отдельную инструкцию с входом и выходом. В `make_user_label("Мира")` на вход поступает имя, внутри действует правило формирования подписи, на выходе появляется строка `"Пользователь: Мира"`. В следующем вызове правило остаётся тем же, а входные данные меняются.

Само выделение функции не гарантирует правильность программы. Нужно проверить, что она делает нужное действие, получает все необходимые данные и возвращает ожидаемый результат.

### 1.1. Границы ответственности

Хорошая функция выполняет одно связное действие. Из её имени, параметров и результата должно быть понятно назначение.

Например, `make_user_label(name)` создаёт строку. Ей не требуется одновременно запрашивать пароль, менять настройки и записывать файл. Эти действия затруднили бы повторное использование и проверку.

## 2. Определение и вызов функции

```python
def add_frame(text):
    framed = f"[{text}]"
    return framed


message = add_frame("Готово")
print(message)  # [Готово]
```

Разберём запись:

| Фрагмент | Значение |
|---|---|
| `def` | Начало определения функции |
| `add_frame` | Имя функции |
| `text` | Параметр, получающий значение при вызове |
| `:` | Начало блока |
| Строки с отступом | Тело функции |
| `return framed` | Возврат результата текущего вызова |
| `add_frame("Готово")` | Вызов с конкретным аргументом |

Когда Python выполняет определение `def`, он создаёт функцию и связывает её с именем. Тело в этот момент не выполняется. Оно выполняется при вызове.

Порядок действий в примере:

1. Создать функцию `add_frame`.
2. Вызвать её с аргументом `"Готово"`.
3. Связать параметр `text` с переданной строкой.
4. Получить новую строку `"[Готово]"`.
5. Вернуть её в место вызова.
6. Присвоить результат имени `message`.

### 2.1. Вызов временно передаёт управление

В строке `message = add_frame("Готово")` присваивание ещё нельзя завершить: правая часть должна сначала получить значение. Поэтому Python выполняет тело `add_frame()`. Когда встречается `return`, значение возвращается на место выражения вызова.

После возврата строку можно мысленно прочитать так:

```python
message = "[Готово]"
```

Это объяснение результата выполнения, а не замена исходной программы. В исходнике остаётся вызов, который сможет обработать и другой аргумент.

| Момент | Данные, доступные внутри вызова | Что делает программа |
|---|---|---|
| Начало вызова | `text` равно `"Готово"` | Переходит к телу функции |
| После первой команды | `framed` равно `"[Готово]"` | Готовит результат |
| На `return` | Возвращаемая строка известна | Завершает вызов |
| После вызова | Снаружи `message` равно `"[Готово]"` | Продолжает основной код |

### 2.2. Имя функции и вызов

```python
def status_message():
    return "Система готова"


saved_function = status_message
message = saved_function()
print(message)  # Система готова
```

Имя без круглых скобок обозначает сам объект функции. Круглые скобки запускают вызов. Даже функция без параметров вызывается со скобками: `status_message()`.

## 3. Параметры и аргументы

**Параметр** — имя в определении. **Аргумент** — значение, переданное при конкретном вызове.

```python
def make_heading(text, level):
    return "#" * level + " " + text


heading = make_heading("Настройки", 2)
print(heading)  # ## Настройки
```

В определении находятся параметры `text` и `level`. При вызове переданы аргументы `"Настройки"` и `2`.

### 3.1. Позиционные аргументы

Вызов `make_heading("Настройки", 2)` связывает значения с параметрами по порядку. Если поменять их местами, функция получит данные с другим смыслом и может завершиться ошибкой.

### 3.2. Именованные аргументы

Можно указать имена параметров:

```python
heading = make_heading(level=2, text="Настройки")
```

В таком вызове порядок именованных аргументов не определяет их назначение.

Можно смешивать формы, записывая обычные позиционные аргументы перед именованными:

```python
heading = make_heading("Настройки", level=2)
```

Один параметр нельзя передать дважды. Вызов `make_heading("Настройки", text="Профиль", level=2)` завершится `TypeError`: `text` получит значение и по позиции, и по имени.

### 3.3. Аргумент может быть выражением

```python
base_level = 1
heading = make_heading("Подраздел", base_level + 1)
```

Перед вызовом вычисляются выражения аргументов. В функцию поступает уже полученное значение 2.

### 3.4. Связь аргументов с параметрами

Имена снаружи не обязаны совпадать с именами параметров:

```python
def add_frame(text):
    return f"[{text}]"


caption = "Профиль"
result = add_frame(caption)
print(result)  # [Профиль]
```

Снаружи строка доступна через имя `caption`, внутри текущего вызова — через параметр `text`. Программа передаёт объект, а не требует одинакового написания переменных.

Аргументы обязательных параметров нельзя просто пропустить. Например, `make_heading("Настройки")` для определения с двумя обязательными параметрами вызовет `TypeError`. Python не знает, какой уровень заголовка мы хотели использовать.

## 4. Возврат результата и вывод на экран

`return` передаёт значение вызывающему коду. `print()` показывает данные на экране.

У программы может быть два разных получателя: человек, читающий экран, и следующий участок кода, использующий результат. Для человека подходит вывод, для следующего вычисления требуется возвращаемое значение.

```python
def make_notice(text):
    return f"Сообщение: {text}"


notice = make_notice("Соединение установлено")
print(notice)
```

Полученную строку можно вывести, сохранить в списке, передать другой функции или сравнить с ожидаемой строкой.

Теперь другая функция:

```python
def show_notice(text):
    print(f"Сообщение: {text}")


result = show_notice("Соединение установлено")
print(result)  # None
```

`show_notice()` выводит сообщение, но не возвращает строку. Результат такого вызова равен `None`.

| Действие | `return` | `print()` |
|---|---|---|
| Передаёт результат вызывающему коду | Да | Сам вызов возвращает `None` |
| Показывает текст человеку | Сам по себе нет | Да |
| Завершает текущий вызов функции | Да | Нет |

### 4.1. Функция без return

Если выполнение дошло до конца функции без `return`, результат равен `None`. Запись `return` без выражения также возвращает `None`.

В Python нет отдельной конструкции «процедура». Функция, выполняющая действие без содержательного результата, остаётся функцией.

### 4.2. Почему надпись на экране не становится результатом

При выполнении `result = show_notice("Соединение установлено")` происходят отдельные события:

1. Внутренний `print()` показывает сообщение на экране.
2. Тело функции заканчивается без `return` со строкой.
3. Результатом вызова становится `None`.
4. Именно `None` присваивается имени `result`.

Экранный вывод не считывается автоматически обратно в переменную. Поэтому функция может выглядеть работающей для человека, но оказаться неудобной для последующего расчёта.

`None` — отдельное значение, обозначающее отсутствие содержательного результата в принятом программой смысле. Это не строка `"None"`, не число 0 и не пустая строка. Проверку на него обычно записывают `result is None`.

## 5. Условия и ранний возврат

`return` завершает только текущий вызов функции. Программа продолжает работать после места вызова.

```python
def connection_label(is_connected):
    if is_connected:
        return "В сети"
    return "Нет соединения"


print(connection_label(True))   # В сети
print(connection_label(False))  # Нет соединения
```

Если условие истинно, выполняется первый `return`. До второго выполнение уже не доходит.

### 5.1. Явный результат на каждом пути

```python
def access_label(is_allowed):
    if is_allowed:
        return "Разрешено"
```

При ложном аргументе эта функция вернёт `None`. Это допустимо только тогда, когда именно такое поведение задумано.

Если по смыслу всегда нужна строка, следует добавить возврат для второго случая:

```python
def access_label(is_allowed):
    if is_allowed:
        return "Разрешено"
    return "Запрещено"
```

Команды после безусловного `return` в том же блоке не выполняются. Размещать там необходимый расчёт или вывод бессмысленно.

### 5.2. Ручной разбор двух вызовов

| Вызов | Условие `if is_connected` | Выполненный возврат | Результат |
|---|---|---|---|
| `connection_label(True)` | Истинно | Первый | `"В сети"` |
| `connection_label(False)` | Ложно | Второй | `"Нет соединения"` |

После каждого вызова полезно спросить: «Может ли выполнение дойти до конца тела, не вернув то, что обещано?» Если да, появляется дополнительный путь с результатом `None`.

## 6. Локальные имена и область видимости

Параметры и обычные присваивания внутри функции создают локальные имена текущего вызова.

```python
def shift_value(value, offset):
    shifted = value + offset
    return shifted


value = 10
result = shift_value(value, 3)

print(value)   # 10
print(result)  # 13
```

Локальное имя `shifted` доступно внутри функции. За её пределами нужно использовать возвращённый результат.

Слово «локальный» означает «относящийся к этому месту выполнения». Каждый новый вызов создаёт собственные связи параметров и локальных имён. Поэтому один вызов с аргументами 10 и 3 не заставляет следующий вызов использовать те же данные.

```python
def shift_value(value, offset):
    shifted = value + offset
    return shifted


first = shift_value(10, 3)
second = shift_value(20, -2)
print(first, second)  # 13 18
```

Во втором вызове параметр `value` равен 20, `offset` равен -2. Возвращённое число первого вызова уже сохранено снаружи в `first`.

### 6.1. Совпадающие имена

```python
def make_message():
    message = "Внутри функции"
    return message


message = "Снаружи функции"
result = make_message()
print(message)  # Снаружи функции
print(result)   # Внутри функции
```

Два имени `message` находятся в разных областях видимости.

### 6.2. Зависимость от внешнего состояния

Функция может читать имя из окружающей области, но скрытые зависимости усложняют проверку. Сравним:

```python
prefix = "INFO"


def make_log_line(text):
    return f"{prefix}: {text}"
```

Результат зависит и от аргумента, и от внешнего `prefix`. Более явный интерфейс:

```python
def make_log_line(text, prefix):
    return f"{prefix}: {text}"
```

Передача данных параметрами позволяет понять зависимости по одному определению. Для рассмотренных примеров `global` не требуется.

<a id="section-7"></a>

## 7. Значения параметров по умолчанию

Параметр может иметь заранее выбранное значение:

```python
def make_log_line(text, prefix="INFO"):
    return f"{prefix}: {text}"


print(make_log_line("Запуск"))
print(make_log_line("Повторное соединение", prefix="WARN"))
```

Результат:

```text
INFO: Запуск
WARN: Повторное соединение
```

Значение по умолчанию используется, только если аргумент не передан. Оно не проверяет тип и не исправляет переданное значение автоматически.

В обычном определении обязательные параметры располагают перед параметрами по умолчанию.

Необязательным становится аргумент в вызове. Сам параметр внутри функции всё равно получает значение: либо переданное явно, либо заранее выбранное. Внутри `make_log_line("Запуск")` параметр `prefix` существует и равен `"INFO"`.

Если передать `prefix=""`, будет использована пустая строка. Python не заменяет её на `"INFO"`: аргумент уже передан. Это помогает отличить пропуск аргумента от передачи пустого значения.

### 7.1. Когда вычисляется значение по умолчанию

Оно вычисляется при выполнении определения функции, а не заново при каждом вызове. Особенно важно помнить об этом для списков и словарей.

## 8. Изменяемое значение по умолчанию

Рассмотрим нежелательное поведение:

```python
def remember_event(event, events=[]):
    events.append(event)
    return events


print(remember_event("открытие"))  # ['открытие']
print(remember_event("закрытие")) # ['открытие', 'закрытие']
```

В обоих вызовах используется один список, созданный при определении функции. В результате второй вызов видит данные первого.

Если при отсутствии аргумента каждый вызов должен создавать новый список, применяют `None`:

```python
def remember_event(event, events=None):
    if events is None:
        events = []
    events.append(event)
    return events


print(remember_event("открытие"))  # ['открытие']
print(remember_event("закрытие")) # ['закрытие']
```

Если вызывающий код явно передаст список, функция по-прежнему добавит событие именно в него. Это поведение нужно учитывать и описывать.

### 8.1. Откуда появляется общий список

В первом определении `events=[]` список создаётся один раз и сохраняется как значение по умолчанию. При первом вызове в него добавляется `"открытие"`. При втором вызове Python снова берёт тот же объект, в котором это событие уже записано.

| Вариант | Первый вызов без списка | Второй вызов без списка |
|---|---|---|
| `events=[]` | Использует общий список | Продолжает изменять тот же список |
| `events=None`, затем `events = []` | Создаёт список в теле | Создаёт другой список в новом вызове |

`is None` в исправленном варианте проверяет специальное значение, а не пустоту коллекции. Если пользователь явно передал пустой список, он должен быть использован как переданный объект.

<a id="section-9"></a>

## 9. Передача изменяемых объектов

При вызове параметр связывается с переданным объектом. Копия автоматически не создаётся.

```python
def add_marker(markers, marker):
    markers.append(marker)


markers = ["начало"]
add_marker(markers, "конец")
print(markers)  # ['начало', 'конец']
```

Параметр и имя снаружи указывают на один список. Метод `append()` меняет этот объект, поэтому результат виден вызывающему коду.

### 9.1. Переприсваивание локального имени

```python
def reset_markers(markers):
    markers = []


markers = ["начало"]
reset_markers(markers)
print(markers)  # ['начало']
```

Здесь изменяется только связь локального имени. Исходный список не очищается.

### 9.2. Возврат нового объекта

```python
def with_marker(markers, marker):
    result = markers.copy()
    result.append(marker)
    return result


original = ["начало"]
extended = with_marker(original, "конец")
print(original)  # ['начало']
print(extended)  # ['начало', 'конец']
```

Из интерфейса и описания функции должно быть ясно, изменяет ли она переданный объект или возвращает новый.

### 9.3. Три разных действия

| Команда внутри функции | Что меняется | Видно ли изменение исходного списка снаружи |
|---|---|---|
| `items.append("новое")` | Содержимое общего объекта | Да |
| `items = []` | Только связь локального имени | Нет |
| `result = items.copy()` | Создаётся новый внешний список | Само копирование исходный объект не меняет |

При передаче списка Python не копирует его содержимое. В вызывающем коде и в параметре появляются способы обратиться к одному объекту. Но присваивание новому имени внутри функции само по себе не меняет связь имени снаружи.

Именно поэтому выражение «функция меняет переменную» слишком неопределённо. Лучше уточнить: меняется содержимое объекта или имя связывается с другим объектом?

<a id="section-10"></a>

## 10. Описание функции и аннотации

Первую строку-документацию внутри функции называют **docstring**:

```python
def make_log_line(text: str, prefix: str = "INFO") -> str:
    """Вернуть строку журнала, не выполняя вывод на экран."""
    return f"{prefix}: {text}"
```

Аннотация `text: str` сообщает ожидаемый тип параметра, `-> str` — тип результата. Они помогают читателю, редактору и средствам анализа.

Обычный Python не проверяет эти аннотации автоматически во время вызова. Передача другого типа не обязательно вызовет ошибку немедленно. Фактическое поведение определяется командами внутри функции.

Полезное описание объясняет смысл параметров, результат и существенные ограничения. Фраза «функция с двумя параметрами» почти ничего не добавляет к коду.

Слово **интерфейс** в данном контексте означает способ пользоваться функцией: как её зовут, что ей нужно передать, что она возвращает и какие изменения выполняет. Это не обязательно окно или кнопки на экране.

Например, описание «принимает строку и возвращает её подпись с префиксом, исходные данные не меняет» помогает написать вызов и проверить результат. Внутренние промежуточные имена для использования функции знать не требуется.

### 10.1. Небольшой интерфейс

Чем меньше независимых действий скрыто в функции, тем проще её вызывать и проверять. Если параметров становится слишком много, полезно пересмотреть назначение функции или объединить связанные сведения в запись.

<a id="section-11"></a>

## 11. Функции вызывают другие функции

```python
def add_frame(text):
    return f"[{text}]"


def make_notice(text, prefix="INFO"):
    framed_prefix = add_frame(prefix)
    return f"{framed_prefix} {text}"


print(make_notice("Соединение установлено"))
# [INFO] Соединение установлено
```

Внешняя функция использует результат внутренней. Такой способ построения называют композицией: из небольших действий собирается более крупное.

При выполнении `return` из `add_frame()` управление возвращается в `make_notice()`. После `return` из `make_notice()` результат поступает в `print()`.

При чтении программы полезно прослеживать цепочку: какие данные переданы, какой результат возвращён и кто его использует.

В примере `make_notice("Соединение установлено")` локальный `prefix` равен `"INFO"`. Вызов `add_frame(prefix)` возвращает `"[INFO]"`. После этого внешняя функция дописывает пробел и сообщение. Только готовая строка поступает в `print()`.

В каждый момент выполняется конкретный вызов. Когда он заканчивается, программа возвращается к ожидавшему его участку. Для начала достаточно уметь проследить такую цепочку из двух функций; сложные цепочки лучше разбивать на промежуточные имена.

<a id="section-12"></a>

## 12. Кортеж tuple

Кортеж — неизменяемая последовательность элементов:

```python
position = (12, 8)
print(position[0])  # 12
print(position[1])  # 8
```

Порядок имеет значение. В примере первое число означает координату `x`, второе — `y`.

Назначение позиций определяется смыслом программы. Кортеж `(12, 8)` сам по себе не хранит имена `x` и `y`; мы договариваемся, что первая позиция — горизонтальная координата. Если значения по позициям трудно запомнить, словарь с именами полей может оказаться понятнее.

Кортеж не обязан состоять из двух элементов. Он может быть пустым, содержать один элемент или длинную последовательность. Пара координат служит небольшим наглядным примером.

Как и список, кортеж допускает индексы, срезы, `len()`, `in` и перебор. Но заменить элемент через `position[0] = 20` нельзя.

### 12.1. Один элемент

```python
single = (5,)
number = (5)
empty = ()

print(type(single))  # <class 'tuple'>
print(type(number))  # <class 'int'>
```

Кортеж формирует запятая. Скобки делают запись явной. Без запятой `(5)` остаётся числом в скобках.

### 12.2. Граница неизменяемости

```python
entry = ("маршрут", ["вход"])
entry[1].append("выход")
print(entry)  # ('маршрут', ['вход', 'выход'])
```

Элементы самого кортежа не заменялись: второй элемент всё ещё тот же список. Но этот вложенный список изменяем. Неизменяемый внешний контейнер не делает все вложенные объекты неизменяемыми.

<a id="section-13"></a>

## 13. Распаковка и несколько результатов

Кортеж можно распаковать в отдельные имена:

```python
position = (12, 8)
x, y = position
print(x, y)  # 12 8
```

Число обычных имён должно совпадать с количеством элементов. Иначе возникнет `ValueError`.

Функция может вернуть кортеж:

```python
def move_point(x, y, dx, dy):
    new_x = x + dx
    new_y = y + dy
    return new_x, new_y


position = move_point(10, 4, 3, -1)
x, y = position
print(position)  # (13, 3)
print(x, y)      # 13 3
```

Выражение `return new_x, new_y` возвращает один объект-кортеж из двух элементов. Фраза «возвращает два значения» описывает удобство использования результата.

Для вызова `move_point(10, 4, 3, -1)` вычисления можно выполнить вручную. Новая горизонтальная координата равна `10 + 3 = 13`, вертикальная — `4 + (-1) = 3`. Поэтому сначала получается кортеж `(13, 3)`, а при распаковке имя `x` получает 13, `y` — 3.

Команда `position = move_point(...)` сохраняет весь кортеж. Команда `x, y = move_point(...)` сразу распаковывает его. Выбор зависит от того, нужен ли дальше результат как одна пара или как два отдельных значения.

Распаковка также встречалась в `for index, value in enumerate(items)`: очередная пара разделяется на два имени.

<a id="section-14"></a>

## 14. Выбор коллекции

Коллекции различаются смыслом доступа и правилами хранения:

| Тип | Что хранит | Как обращаться | Изменяемость | Повторы |
|---|---|---|---|---|
| `list` | Последовательность элементов | По индексу | Да | Сохраняются |
| `tuple` | Фиксированную последовательность | По индексу | Сам кортеж неизменяем | Сохраняются |
| `dict` | Соответствия ключей значениям | По ключу | Да | Ключи уникальны, значения могут повторяться |
| `set` | Уникальные элементы | Проверять принадлежность | Да | Не сохраняются |

Примеры выбора:

- очередь действий, где важны порядок и повторы: список;
- пара координат с фиксированным назначением позиций: кортеж;
- настройки с полями `theme`, `language`, `sound`: словарь;
- набор разрешённых кодов команд: множество.

Словарь сохраняет порядок вставки ключей, но его главный способ доступа связан с ключом. Множество не предоставляет гарантированного порядка обхода и не поддерживает индексы.

### 14.1. Как выбирать без заучивания таблицы

Если важна позиция элемента и число элементов будет меняться, начните со списка. Если передаётся фиксированная группа значений с понятным порядком, рассмотрите кортеж. Если нужно обратиться к данным по имени поля, используйте словарь. Если главный вопрос звучит «входит ли значение в набор?» и повторы не нужны, подходит множество.

Тип нельзя выбрать только по внешним скобкам. Нужно сначала определить смысл данных. Например, два одинаковых события в истории являются двумя событиями, поэтому множество потеряло бы информацию. А два одинаковых разрешения в наборе прав доступа не добавляют нового смысла.

<a id="section-15"></a>

## 15. Словарь dict

Словарь связывает ключи со значениями:

```python
settings = {
    "theme": "dark",
    "language": "ru",
    "sound": True,
}

print(settings["theme"])     # dark
print(settings["language"])  # ru
```

Вместо запоминания позиции поля мы обращаемся по его имени. Значения могут иметь разные типы: строка, число, логическое значение, список или другой словарь.

### 15.1. Ключ уникален

```python
settings = {"theme": "light"}
settings["theme"] = "dark"
print(settings)  # {'theme': 'dark'}
```

Существующее значение заменилось. Второй записи с тем же ключом не появилось.

В паре `"theme": "dark"` слева от двоеточия расположен ключ, справа — значение. При записи `settings["theme"]` в квадратных скобках находится строковый ключ. Это не индекс: мы не спрашиваем «дай элемент номер theme», а ищем поле с точным именем.

Ключи `"theme"` и `"Theme"` различаются, потому что строки чувствительны к регистру. Ошибка в написании ключа может создать новое поле при присваивании или вызвать `KeyError` при чтении.

### 15.2. Добавление поля

```python
settings["font_size"] = 16
```

Если ключа ещё не было, присваивание создаёт новую пару.

### 15.3. Удаление поля

```python
settings = {"theme": "dark", "sound": True}
removed = settings.pop("sound")
print(removed)   # True
print(settings)  # {'theme': 'dark'}
```

`pop()` возвращает удалённое значение. Удаление через `del settings["theme"]` убирает пару без возвращаемого результата.

<a id="section-16"></a>

## 16. Отсутствующий ключ и get

Доступ через квадратные скобки предполагает, что ключ существует:

```python
settings = {"theme": "dark"}
print(settings["language"])
```

Этот фрагмент вызовет `KeyError`.

Если отсутствие поля является допустимым случаем, можно использовать `get()`:

```python
settings = {"theme": "dark"}
language = settings.get("language", "ru")
print(language)  # ru
print(settings)  # {'theme': 'dark'}
```

`get()` возвращает запасное значение, но не добавляет ключ в словарь.

Без второго аргумента запасной результат равен `None`:

```python
print(settings.get("language"))  # None
```

### 16.1. Отсутствие и явно записанный None

Если словарь содержит `{"language": None}`, вызов `get("language", "ru")` вернёт `None`. Значение по умолчанию используется только для отсутствующего ключа.

### 16.2. Оператор in проверяет ключи

```python
settings = {"theme": "dark"}
print("theme" in settings)  # True
print("dark" in settings)   # False
print("dark" in settings.values())  # True
```

Для проверки наличия поля используйте `key in dictionary`.

### 16.3. Какой способ чтения выбрать

Если поле обязательно и его отсутствие означает ошибку в данных, квадратные скобки помогают сразу обнаружить проблему. Например, имя устройства требуется для подписи, и запись без него не соответствует ожидаемому формату.

Если поле необязательно, `get()` позволяет явно выбрать запасное значение. Например, при отсутствии настройки языка программа использует `"ru"`. Это поведение должно быть осознанным: универсальная замена всех обращений на `get()` может спрятать пропущенные обязательные поля.

**Самопроверка:** после `value = settings.get("font_size", 14)` появится ли ключ `font_size`? Нет. Чтобы сохранить настройку, нужна отдельная команда `settings["font_size"] = value`.

<a id="section-17"></a>

## 17. Перебор словаря

```python
settings = {"theme": "dark", "language": "ru"}

for key in settings:
    print(key)
```

Обычный цикл перебирает ключи. Метод `values()` позволяет перебрать значения, `items()` — пары:

```python
for key, value in settings.items():
    print(f"{key}: {value}")
```

Здесь используется распаковка очередной пары.

Порядок действий в `for key, value in settings.items()` такой: метод даёт очередную пару, первое значение связывается с `key`, второе — с `value`, затем выполняется тело цикла.

Для словаря `{"theme": "dark", "language": "ru"}`:

| Итерация | `key` | `value` | Вывод |
|---:|---|---|---|
| 1 | `"theme"` | `"dark"` | `theme: dark` |
| 2 | `"language"` | `"ru"` | `language: ru` |

Обычный `for key in settings` получает только первый столбец. Для значения тогда потребуется дополнительное обращение `settings[key]`.

### 17.1. Порядок вставки и сортировка

Пары обходятся в порядке добавления ключей. Обновление существующего значения не переносит ключ в конец.

Если нужен алфавитный порядок строковых ключей:

```python
for key in sorted(settings):
    print(f"{key}: {settings[key]}")
```

Сортировка должна соответствовать требованию вывода. Порядок вставки и алфавитный порядок являются разными правилами.

### 17.2. Изменение размера при обходе

Не следует добавлять или удалять ключи непосредственно при обходе того же словаря. Это может привести к `RuntimeError`. Сначала соберите нужные ключи отдельно или постройте новый словарь.

<a id="section-18"></a>

## 18. Коллекции внутри коллекций

Словарь может содержать список и другой словарь:

```python
panel = {
    "caption": "Терминал",
    "size": {"width": 800, "height": 500},
    "buttons": ["Открыть", "Закрыть"],
}

print(panel["size"]["width"])  # 800
print(panel["buttons"][0])     # Открыть
```

Каждый следующий шаг относится к объекту, полученному на предыдущем:

1. `panel["size"]` возвращает словарь размеров.
2. `["width"]` читает поле из него.

### 18.1. Список записей

```python
windows = [
    {"caption": "Терминал", "visible": True},
    {"caption": "Настройки", "visible": False},
]

for window in windows:
    print(window["caption"], window["visible"])
```

Внешний список определяет последовательность записей. Каждый словарь описывает одну запись через имена полей.

Такой способ хранения требует согласованности: если программа ожидает поле `caption`, оно должно присутствовать в каждой обязательной записи либо отсутствие нужно обработать.

<a id="section-19"></a>

## 19. Копирование словарей и вложенных данных

```python
original = {"theme": "light", "font_size": 14}
changed = original.copy()
changed["theme"] = "dark"

print(original["theme"])  # light
print(changed["theme"])   # dark
```

`copy()` создаёт отдельный внешний словарь. Но вложенные изменяемые объекты остаются общими:

```python
original = {"buttons": ["Открыть"]}
changed = original.copy()
changed["buttons"].append("Закрыть")

print(original["buttons"])  # ['Открыть', 'Закрыть']
```

Оба словаря содержат ссылку на один список. Это **поверхностное копирование**.

Если нужно независимо изменить только список кнопок, можно скопировать его отдельно:

```python
changed = original.copy()
changed["buttons"] = original["buttons"].copy()
```

Выбор глубины копирования зависит от того, какие вложенные объекты программа собирается менять.

### 19.1. Почему копирование снаружи не копирует всё внутри

Представьте словарь как набор подписанных ссылок на значения. `original.copy()` создаёт другой набор подписей, но для вложенного списка обе записи сначала ведут к одному и тому же объекту.

Поэтому замена `changed["buttons"] = [...]` меняет только поле нового словаря, а `changed["buttons"].append(...)` изменяет общий вложенный список. Отличие связано с тем, к какому объекту применяется операция.

Если нужна независимость списка кнопок, его копию следует создать **до** первого изменения общего списка. Копирование после изменения не восстановит прежнее состояние `original`.

<a id="section-20"></a>

## 20. Множество set

Множество хранит уникальные элементы:

```pytоhon
commands = {"open", "close", "open"}
print(len(commands))       # 2
print("open" in commands)  # True
```

Повторный элемент не создаёт отдельной записи.

### 20.1. Пустое множество

```python
empty_set = set()
empty_dict = {}
print(type(empty_set))   # <class 'set'>
print(type(empty_dict))  # <class 'dict'>
```

Фигурные скобки без элементов обозначают словарь.

### 20.2. Добавление и удаление

```python
commands = {"open"}
commands.add("close")
commands.add("open")
commands.discard("pause")
print(sorted(commands))  # ['close', 'open']
```

`discard()` не вызывает ошибку при отсутствии элемента. `remove()` в таком случае вызывает `KeyError`.

### 20.3. Порядок и индексы

Выражение `commands[0]` недопустимо. Множество не является индексируемой последовательностью.

Не следует ожидать определённого порядка печати или обхода. Для воспроизводимого вывода строк используйте `sorted(commands)`. Получится список, а само множество не изменится.

### 20.4. Что сохраняется при преобразовании в множество

```python
events = ["open", "close", "open"]
unique_events = set(events)

print(len(events))         # 3
print(len(unique_events))  # 2
```

В списке записаны три события. Множество отвечает на другой вопрос: какие виды событий встретились? Оно уже не хранит, что событие `open` произошло дважды, и не предназначено для восстановления исходной последовательности.

Таким образом, выбор множества означает согласие отказаться от повторов и порядка. Это удобно для набора доступных команд, но не подходит для полной истории действий.

<a id="section-21"></a>

## 21. Операции над множествами

Представим два набора поддерживаемых форматов:

```python
editor_formats = {"txt", "md", "html"}
viewer_formats = {"txt", "html", "pdf"}
```

| Выражение | Смысл | Отсортированный результат |
|---|---|---|
| `editor_formats & viewer_formats` | Пересечение | `['html', 'txt']` |
| `editor_formats \| viewer_formats` | Объединение | `['html', 'md', 'pdf', 'txt']` |
| `editor_formats - viewer_formats` | Разность | `['md']` |
| `editor_formats ^ viewer_formats` | Есть только в одном наборе | `['md', 'pdf']` |

Разность зависит от порядка операндов. `viewer_formats - editor_formats` даст множество с `pdf`.

### 21.1. Чтение операций обычными словами

Пересечение отвечает на вопрос «какие форматы понимают обе программы?». Поэтому `md` не входит в пересечение: он есть только у редактора. Объединение отвечает «какие форматы понимает хотя бы одна программа?». В нём окажутся все четыре различных формата.

Разность `editor_formats - viewer_formats` показывает возможности редактора, которых нет у просмотрщика. Здесь остаётся только `md`. Симметрическая разность показывает отличия в обе стороны: `md` и `pdf`.

Для пустого набора результат тоже понятен. Пересечение с пустым множеством пусто, потому что общих элементов нет. Объединение с пустым множеством сохраняет элементы другого набора.

### 21.2. Подмножество

```python
required_formats = {"txt", "md"}
supported_formats = {"txt", "md", "html"}

print(required_formats <= supported_formats)  # True
```

Здесь `<=` означает: каждый элемент первого множества входит во второе. Это проверка полноты поддержки, а не числовое сравнение размеров.

Если повторы и исходный порядок имеют смысл, преобразование в множество потеряет часть информации. Тогда следует сохранить исходную последовательность.

<a id="section-22"></a>

## 22. Допустимые ключи и элементы множества

Ключ словаря и элемент множества должны быть **хешируемыми**. Для начала достаточно понимать это как требование типа: объект должен поддерживать устойчивый хеш и согласованное сравнение для использования в такой структуре.

Строки и целые числа подходят. Списки, словари и обычные множества — нет.

```python
pixel_colors = {
    (0, 0): "black",
    (1, 0): "white",
}

print(pixel_colors[(1, 0)])  # white
```

Кортеж целых чисел подходит в качестве ключа. Кортеж со списком внутри не подойдёт, потому что список не хешируем.

### 22.1. frozenset

`frozenset` создаёт неизменяемое множество:

```python
permissions = frozenset({"read", "write"})
print("read" in permissions)  # True
```

У него нет методов добавления и удаления. Его можно использовать там, где требуется хешируемый набор. Все элементы такого набора также должны быть хешируемыми.

Подробности внутреннего устройства хеш-таблиц выходят за рамки этой лекции. Сейчас важно выбирать допустимые типы и понимать, почему список нельзя поставить на место ключа.

### 22.2. Практический смысл ограничения

Словарю и множеству нужно уметь снова найти уже помещённый объект. Поэтому они используют устойчивые правила определения и сравнения ключей. Если бы список, содержимое которого свободно меняется, разрешалось использовать как обычный ключ, изменение списка могло бы нарушить эти правила.

Для изучаемых типов можно пользоваться ориентиром: строка, число и кортеж из подходящих элементов годятся; список, словарь и `set` не годятся. Это ориентир для этих примеров, а не общее правило для любых пользовательских типов.

<a id="section-23"></a>

## 23. Общий пример: сообщение о состоянии устройства

Объединим несколько конструкций в небольшом примере. Одна запись описывает устройство: имя, координаты, состояние и доступные способы связи. Функция формирует сообщение и не меняет запись.

```python
def state_label(is_online):
    if is_online:
        return "доступно"
    return "недоступно"


def describe_device(device):
    x, y = device["position"]
    state = state_label(device["online"])
    return f"{device['name']}: {state}, позиция ({x}, {y})"


device = {
    "name": "Датчик-1",
    "position": (4, 9),
    "online": True,
    "connections": {"wifi", "usb"},
}

message = describe_device(device)
print(message)
print("usb" in device["connections"])
```

Результат:

```text
Датчик-1: доступно, позиция (4, 9)
True
```

### 23.1. Почему выбраны такие типы

| Часть данных | Тип | Причина |
|---|---|---|
| Вся запись | `dict` | Доступ к полям по смысловым именам |
| Положение | `tuple` | Фиксированная упорядоченная пара координат |
| Способы связи | `set` | Важна принадлежность способа, повторы не нужны |
| Сообщение | `str` | Готовый текст для вывода |

### 23.2. Как проходит вызов

1. Параметр `device` связывается с переданным словарём.
2. Кортеж координат распаковывается в локальные `x` и `y`.
3. `state_label()` превращает логическое состояние в подпись.
4. F-строка собирает сообщение.
5. `return` отдаёт строку вызывающему коду.
6. Внешний `print()` показывает полученный результат.

Функция `describe_device()` только читает словарь. Добавление поля или замена значения потребовали бы отдельного действия и другого договора о поведении.

### 23.3. Разбор значений при одном вызове

| Команда или выражение | Значение |
|---|---|
| `device["position"]` | `(4, 9)` |
| После `x, y = ...` | `x = 4`, `y = 9` |
| `device["online"]` | `True` |
| `state_label(True)` | `"доступно"` |
| `device["name"]` | `"Датчик-1"` |
| Результат `describe_device(device)` | `"Датчик-1: доступно, позиция (4, 9)"` |

Если изменить `online` на `False` и повторить вызов, сообщение станет содержать слово `недоступно`. Уже полученная ранее строка `message` сама не пересчитается: для нового состояния нужен новый вызов функции.

Проверка `"usb" in device["connections"]` сначала читает множество способов связи, затем проверяет принадлежность. Входной словарь, вложенный кортеж и множество остаются прежними, потому что программа здесь только читает данные.

## 24. Модули и точка входа

По мере роста программы связанные функции удобно переносить в отдельный файл-модуль.

В файле `labels.py`:

```python
def add_frame(text):
    return f"[{text}]"
```

В соседнем файле `app.py`:

```python
from labels import add_frame


def main():
    message = add_frame("Готово")
    print(message)


if __name__ == "__main__":
    main()
```

`from labels import add_frame` делает функцию доступной по имени. Расширение `.py` в импорте не указывается.

При прямом запуске `app.py` переменная `__name__` равна `"__main__"`, поэтому выполняется `main()`. При импорте `app` этот блок пропускается.

Код верхнего уровня модуля выполняется при первом обычном импорте в процессе. Поэтому взаимодействие с пользователем удобно помещать в `main()` под условие прямого запуска.

### 24.1. Что происходит при запуске файла

Если выполнить `python app.py`, интерпретатор сначала импортирует функцию из `labels.py`, затем создаёт функцию `main`, проверяет условие внизу файла и вызывает `main()`. На экране появится `[Готово]`.

Если другой файл выполнит `import app`, определение `main()` будет доступно в модуле, но условие прямого запуска окажется ложным. Сообщение не появится само по себе.

Имя `main` является соглашением программистов. Особое значение имеет условие с `__name__`, а не само название функции. Оба файла для этого примера нужно сохранить рядом; код из разных подписанных файлов не следует бездумно объединять в один.

<a id="section-25"></a>

## 25. Проверка функций

Функцию, возвращающую значение, можно проверить без ручного ввода:

```python
def add_frame(text):
    return f"[{text}]"


assert add_frame("Готово") == "[Готово]"
assert add_frame("") == "[]"
assert add_frame("А Б") == "[А Б]"
print("Проверки пройдены")
```

`assert` с истинным условием ничего не выводит. Ложное условие вызывает `AssertionError`.

### 25.1. Что проверять

Для функции формирования текста полезны обычная строка, пустая строка и строка с пробелами. Для функции с несколькими ветвями нужно вызвать каждую ветвь.

Если обещано сохранить исходные данные, проверяется и это свойство:

```python
def with_marker(markers, marker):
    return markers + [marker]


original = ["вход"]
result = with_marker(original, "выход")
assert result == ["вход", "выход"]
assert original == ["вход"]
assert result is not original
```

Ожидаемый ответ задают независимо от проверяемого алгоритма.

### 25.2. Как читать одну проверку

В строке `assert add_frame("Готово") == "[Готово]"` сначала вызывается функция. Затем её результат сравнивается с заранее известной строкой. Если сравнение истинно, выполнение продолжается. Если ложно, Python останавливает этот запуск с `AssertionError`.

Не следует получать «ожидаемую строку» повторным вызовом той же функции. Два одинаковых неправильных результата тоже совпадут, а ошибка останется незамеченной.

Проверки `result == ["вход", "выход"]`, `original == ["вход"]` и `result is not original` отвечают на разные вопросы: верно ли содержимое результата, сохранены ли исходные данные и создан ли отдельный объект.

### 25.3. Ограничение assert

Учебные проверки через `assert` подходят для проверки предположений и результатов. Они могут отключаться при оптимизированном запуске Python, поэтому обязательную проверку пользовательских данных нельзя основывать только на них.

<a id="section-26"></a>

## 26. Типичные ошибки

| Ошибка | Что происходит | Как проверить |
|---|---|---|
| Имя функции записано без `()` | Вызов не выполняется | Найти место фактического вызова |
| `print()` принят за возврат | Результат вызова равен `None` | Присвоить результат и проверить тип |
| В одной ветви нет `return` | Иногда возвращается `None` | Выполнить все ветви |
| Использовано локальное имя снаружи | Обычно `NameError` | Читать результат через `return` |
| Переданный список неожиданно изменён | Меняется общий объект | Сравнить исходные данные после вызова |
| Список записан значением по умолчанию | Вызовы делят один список | Вызвать функцию дважды |
| `(5)` принят за кортеж | Получается `int` | Проверить запятую и `type()` |
| Чтение отсутствующего ключа через `[]` | `KeyError` | Проверить ключ или использовать `get()` |
| `in` словаря принят за поиск значений | Проверяются ключи | При необходимости использовать `values()` |
| `{}` принято за множество | Создаётся `dict` | Пустое множество создавать через `set()` |
| Ожидается фиксированный порядок множества | Вывод не соответствует ожиданию | Сортировать перед показом |
| Список используется как ключ | `TypeError` | Выбрать хешируемый тип |
| Поверхностная копия принята за глубокую | Вложенные объекты остаются общими | Изменить вложенный список и сравнить |

### 26.1. Как разбирать непонятное поведение

Сначала установите, какой объект передан функции. Затем проверьте, меняет ли функция объект или только переприсваивает локальное имя. После этого проследите, какое значение возвращается и где оно используется.

Для коллекций задайте отдельный вопрос: обращение выполняется по индексу, по ключу или через проверку принадлежности? Это помогает обнаружить неверно выбранную структуру.

## 27. Вопросы с разбором

### 27.1. Выполняется ли тело при записи def?

Нет. Определение создаёт функцию. Её тело выполняется при вызове.

### 27.2. Чем параметр отличается от аргумента?

Параметр записан в определении, аргумент передаётся в конкретном вызове.

### 27.3. Что возвращает функция без return?

`None`, если выполнение доходит до конца без явного возвращаемого значения.

### 27.4. Можно ли продолжать программу после return?

Да. Завершается текущий вызов функции, а вызывающий код продолжает выполнение.

### 27.5. Почему изменение параметра иногда видно снаружи?

Если параметр связан с изменяемым объектом и функция меняет сам объект, изменение видно всем именам, связанным с ним.

### 27.6. Создаёт ли присваивание параметру новый список для вызывающего имени?

Нет. Команда `items = []` перепривязывает локальное имя. Для очистки общего списка потребовалась бы операция над самим объектом, например `items.clear()`.

### 27.7. Когда создаётся список по умолчанию в def f(items=[])?

При выполнении определения функции. Без явного аргумента вызовы будут использовать один и тот же список.

### 27.8. Является ли аннотация str проверкой типа?

В обычном выполнении нет. Она описывает ожидаемый интерфейс и может использоваться внешними средствами анализа.

### 27.9. Почему нужен знак запятой в (5,)?

Потому что `(5)` является числом в скобках. Запятая формирует кортеж из одного элемента.

### 27.10. Можно ли изменить список внутри кортежа?

Да. Кортеж не позволяет заменить свою ссылку на элемент, но вложенный список сохраняет собственную изменяемость.

### 27.11. Добавляет ли get запасное значение в словарь?

Нет. Метод только возвращает значение. Для добавления нужно присваивание по ключу или другая операция изменения словаря.

### 27.12. Что проверяет выражение key in dictionary?

Наличие ключа. Для поиска среди значений используется `dictionary.values()`.

### 27.13. Какой порядок сохраняет словарь?

Порядок вставки ключей. Он не означает автоматическую сортировку.

### 27.14. Чем {} отличается от set()?

`{}` создаёт пустой словарь, `set()` — пустое множество.

### 27.15. Можно ли прочитать первый элемент множества по индексу?

Нет. У множества нет доступа по индексу и гарантированного порядка элементов.

### 27.16. Когда кортеж подходит в качестве ключа?

Когда все его элементы хешируемы. Кортеж координат из целых чисел подходит, кортеж со списком внутри — нет.

### 27.17. Почему для позиции устройства выбран кортеж?

Координаты образуют фиксированную пару с важным порядком `x`, `y`. Распаковка делает назначение обеих позиций явным.

### 27.18. Почему функция формирования сообщения возвращает строку?

Тогда вызывающий код сам выбирает, вывести её, сохранить или сравнить. Для проверки функции не требуется перехватывать экранный вывод.

## 28. Краткий словарь

| Термин | Значение |
|---|---|
| Функция | Именованный объект, который можно вызвать для выполнения действия |
| Определение | Создание функции с именем, параметрами и телом |
| Вызов | Запуск функции с аргументами |
| Параметр | Имя, объявленное в определении функции |
| Аргумент | Значение, передаваемое при вызове |
| Возвращаемое значение | Результат вызова, поступающий вызывающему коду |
| Локальное имя | Имя, действующее в области текущего вызова функции |
| Побочный эффект | Изменение состояния за пределами возвращаемого результата, например вывод или изменение переданного объекта |
| Значение по умолчанию | Аргумент, используемый при пропуске соответствующего параметра в вызове |
| Docstring | Строка-документация в начале тела функции |
| Аннотация | Описание ожидаемого типа параметра или результата |
| Композиция | Построение действия через вызовы более простых функций |
| Коллекция | Объект, объединяющий несколько значений |
| Кортеж | Неизменяемая последовательность элементов |
| Распаковка | Связывание элементов последовательности с отдельными именами |
| Словарь | Изменяемое соответствие уникальных ключей значениям |
| Ключ | Объект, по которому находится значение в словаре |
| Множество | Коллекция уникальных хешируемых элементов без индексов |
| Пересечение | Элементы, входящие в оба множества |
| Объединение | Элементы хотя бы одного множества |
| Разность | Элементы первого множества, отсутствующие во втором |
| Хешируемость | Свойство, позволяющее использовать объект как ключ словаря или элемент множества |
| Поверхностная копия | Новый внешний контейнер с прежними ссылками на вложенные объекты |
| Модуль | Файл Python с определениями и кодом, доступный для импорта |
| Точка входа | Место, с которого организован основной сценарий запуска |

При проектировании функции определите её входные данные, результат и допустимые изменения объектов. При выборе коллекции установите, нужен ли порядок, допустимы ли повторы и как программа будет обращаться к значениям. Эти решения делают код понятнее ещё до записи отдельных команд.
