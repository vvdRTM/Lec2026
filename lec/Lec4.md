## 1. Логические значения и сравнения

Условие программы должно дать один из двух ответов: истина или ложь. В Python для этого существуют значения типа `bool`:

```python
True
False
```

Они записываются с заглавной буквы. Это не строки, поэтому кавычки не нужны.

Сравнение двух значений возвращает `True` или `False`:

```text
>>> 5 > 3
True
>>> 5 == 3
False
>>> 5 != 3
True
```

Основные операции сравнения:

| Запись | Смысл | Пример | Результат |
|---|---|---|---|
| `==` | Равно | `5 == 5` | `True` |
| `!=` | Не равно | `5 != 5` | `False` |
| `<` | Меньше | `3 < 5` | `True` |
| `<=` | Меньше или равно | `5 <= 5` | `True` |
| `>` | Больше | `7 > 2` | `True` |
| `>=` | Больше или равно | `7 >= 8` | `False` |

Результат можно сохранить в переменной:

```python
age = 17
is_adult = age >= 18

print(is_adult)  # False
print(type(is_adult))  # <class 'bool'>
```

Имя `is_adult` читается как вопрос: «является ли пользователь взрослым?». Для логических переменных часто используют начала `is_`, `has_`, `can_`, `need_`.

### 1.1. Присваивание и сравнение

Знак `=` присваивает значение:

```python
score = 80
```

Запись `==` сравнивает значения:

```python
score == 80
```

Первая строка меняет состояние программы. Вторая вычисляет логическое значение. В условии `if` нужно сравнение:

```python
if score == 80:
    print("Ровно 80 баллов")
```

Запись `if score = 80:` является синтаксической ошибкой. Python не принимает присваивание в таком месте.

### 1.2. Числа нужно сравнивать как числа

`input()` возвращает строку. Строки сравниваются посимвольно, а не по числовому значению:

```text
>>> "10" < "2"
True
```

Первый символ строки `"10"` равен `"1"`, а `"1"` располагается раньше `"2"`. Для числового сравнения требуется преобразование:

```python
first = int(input("Первое число: "))
second = int(input("Второе число: "))

print(first < second)
```

При вводе `10` и `2` программа напечатает `False`.

### 1.3. Сравнения строк

Равенство строк полезно при выборе команды:

```python
operation = input("Операция: ")
print(operation == "+")
```

Регистр и пробелы входят в строку. Значения `"стоп"`, `"Стоп"` и `" стоп"` различаются. Если условие задания требует игнорировать регистр или пробелы, это нужно отдельно записать в алгоритме. В работах №3–4 сравнивайте строки точно по заданному формату.

## 2. Истинность значений

Условие `if` может получать не только готовое значение `True` или `False`. Python преобразует значение к логическому типу.

Ложными считаются, в частности:

- число `0` и дробное число `0.0`;
- пустая строка `""`;
- пустые коллекции, которые будут изучаться позднее;
- специальное значение `None`.

Ненулевое число и непустая строка считаются истинными:

```text
>>> bool(0)
False
>>> bool(5)
True
>>> bool("")
False
>>> bool("0")
True
```

Строка `"0"` непустая, поэтому её логическое значение истинно. Это ещё одна причина явно преобразовывать числовой ввод.

В учебных задачах предпочтительнее записывать проверку так, чтобы смысл был виден:

```python
if count > 0:
    print("Количество положительное")
```

Запись `if count:` короче, но означает только «значение не ноль». Если задача говорит именно о положительном количестве, сравнение `count > 0` точнее.

## 3. Условная конструкция if

Простейший вариант выполняет блок только при истинном условии:

```python
temperature = int(input("Температура: "))

if temperature < 0:
    print("На улице мороз")

print("Проверка завершена")
```

Если температура отрицательная, программа напечатает две строки. Если температура равна нулю или положительна, блок `if` пропускается, но последняя строка выполняется в любом случае.

Состав конструкции:

```text
if условие:
    команда внутри блока
    ещё одна команда внутри блока
команда после блока
```

После условия ставится двоеточие. Команды внутри блока сдвигаются вправо на одинаковое расстояние. В курсе используем четыре пробела на один уровень.

### 3.1. Отступ является частью синтаксиса

Следующий код неверен:

```text
if temperature < 0:
print("Мороз")
```

После строки `if` Python ожидает блок с отступом и выдаст `IndentationError`.

Другой неверный вариант:

```text
if temperature < 0:
    print("Мороз")
      print("Нужна тёплая одежда")
```

У двух команд одного блока разные отступы. Редактор может визуально скрывать смешение табуляции и пробелов, поэтому используйте пробелы последовательно.

### 3.2. if и else

Когда есть два взаимоисключающих результата, используется `else`:

```python
number = int(input("Число: "))

if number % 2 == 0:
    print("Чётное")
else:
    print("Нечётное")
```

У целого числа остаток от деления на 2 равен нулю только для чётных чисел. Выполнится ровно одна ветвь.

У `else` нет собственного условия. Эта ветвь означает: все предыдущие условия одной цепочки оказались ложными.

## 4. Цепочка if elif else

Для трёх и более взаимоисключающих случаев применяется `elif`:

```python
score = int(input("Баллы от 0 до 100: "))

if score < 0 or score > 100:
    print("Ошибка: баллы вне диапазона")
elif score >= 80:
    print("Высокий результат")
elif score >= 50:
    print("Зачёт")
else:
    print("Нужна доработка")
```

Проверки идут сверху вниз. Как только найдено истинное условие, выполняется его блок, а остальные части этой цепочки пропускаются.

Для `score = 85`:

1. `score < 0 or score > 100` ложно.
2. `score >= 80` истинно.
3. Печатается `Высокий результат`.
4. Проверка `score >= 50` и ветвь `else` уже не выполняются.

Для `score = 80` также выбирается высокая категория: операция `>=` включает границу.

### 4.1. Порядок ветвей

Рассмотрим неверный порядок:

```python
if score >= 50:
    print("Зачёт")
elif score >= 80:
    print("Высокий результат")
```

При `score = 90` первое условие уже истинно. До второй ветви программа не дойдёт. Более строгий высокий порог нужно поставить раньше:

```python
if score >= 80:
    print("Высокий результат")
elif score >= 50:
    print("Зачёт")
else:
    print("Нужна доработка")
```

При движении по нижним границам категории обычно располагают от большей границы к меньшей. При движении по верхним границам можно идти от меньшей к большей:

```python
if score < 50:
    print("Нужна доработка")
elif score < 80:
    print("Зачёт")
else:
    print("Высокий результат")
```

Обе версии корректны для значений от 0 до 100.

### 4.2. else не обязателен

Цепочка может закончиться без `else`, если при отсутствии подходящего условия ничего делать не требуется:

```python
if temperature < 0:
    print("Возможен лёд")
elif temperature > 30:
    print("Очень жарко")
```

При температуре 15 блоки не выполняются. Это допустимо, если именно такое поведение задумано.

## 5. Несколько if и вложенные условия

Отдельные конструкции `if` проверяются независимо:

```python
number = 6

if number > 0:
    print("Положительное")

if number % 2 == 0:
    print("Чётное")
```

Программа напечатает обе характеристики. Число одновременно положительное и чётное.

Если заменить второй `if` на `elif`, будет выбрана только первая подходящая характеристика:

```python
if number > 0:
    print("Положительное")
elif number % 2 == 0:
    print("Чётное")
```

При `number = 6` вторая строка не появится. Это не ошибка Python, а неверно выбранная структура алгоритма.

### 5.1. Когда нужны отдельные if

Используйте отдельные `if`, если свойства могут выполняться одновременно:

- число положительное и чётное;
- пользователь совершеннолетний и имеет билет;
- точка находится на правой и верхней границах прямоугольника;
- число кратно 2 и кратно 3.

Используйте одну цепочку, если требуется выбрать одну категорию:

- низкий, средний или высокий уровень;
- сложение, вычитание, умножение или деление;
- число отрицательное, ноль или положительное.

### 5.2. Вложенный if

Блок условия может содержать другое условие:

```python
operation = input("Операция: ")

if operation == "/":
    second = float(input("Делитель: "))
    if second == 0:
        print("Деление на ноль запрещено")
    else:
        print(10 / second)
```

Проверка делителя имеет смысл только для операции деления, поэтому вложение логично. Каждый уровень добавляет четыре пробела.

Слишком глубокая вложенность затрудняет чтение. Если условие можно понятно выразить с помощью `and` или `or`, часто это проще.

## 6. Логические операторы

Сложное условие объединяет несколько простых проверок.

| Оператор | Результат истинен, когда | Пример |
|---|---|---|
| `and` | Истинны обе части | `age >= 18 and has_ticket` |
| `or` | Истинна хотя бы одна часть | `day == "сб" or day == "вс"` |
| `not` | Условие справа ложно | `not is_ready` |

### 6.1. Оператор and

Для допуска к экзамену могут одновременно требоваться зачёт и регистрация:

```python
has_credit = True
is_registered = False

if has_credit and is_registered:
    print("Допуск есть")
else:
    print("Допуска нет")
```

Результат: `Допуска нет`, потому что второе условие ложно.

Таблица истинности `and`:

| X | Y | X and Y |
|---|---|---|
| `False` | `False` | `False` |
| `False` | `True` | `False` |
| `True` | `False` | `False` |
| `True` | `True` | `True` |

### 6.2. Оператор or

Ошибка диапазона возникает, если значение меньше нижней границы **или** больше верхней:

```python
if score < 0 or score > 100:
    print("Ошибка диапазона")
```

Таблица истинности `or`:

| X | Y | X or Y |
|---|---|---|
| `False` | `False` | `False` |
| `False` | `True` | `True` |
| `True` | `False` | `True` |
| `True` | `True` | `True` |

### 6.3. Оператор not

`not` меняет логическое значение на противоположное:

```python
is_finished = False

if not is_finished:
    print("Работа ещё не завершена")
```

Часто условие можно записать без `not` более прямо. Например, `not number == 0` обычно читается хуже, чем `number != 0`.

### 6.4. Приоритет и скобки

Сначала выполняются сравнения, затем `not`, затем `and`, затем `or`:

```python
result = age >= 18 and has_ticket or is_teacher
```

Это выражение означает:

```python
result = (age >= 18 and has_ticket) or is_teacher
```

Даже если приоритет известен, скобки помогают явно показать структуру сложного правила.

### 6.5. Короткое вычисление

Python вычисляет логическое выражение слева направо и прекращает работу, когда результат уже известен.

```python
if second != 0 and first / second > 2:
    print("Частное больше двух")
```

Если `second == 0`, левая часть `and` ложна. Всё выражение уже не может стать истинным, поэтому деление не выполняется. Порядок частей важен: безопасную проверку нулевого делителя нужно поставить слева.

## 7. Диапазоны и принадлежность прямоугольнику

Python поддерживает цепочку сравнений:

```python
0 <= score <= 100
```

Она означает одновременно:

```python
0 <= score and score <= 100
```

Обе границы включены. Для строгого внутреннего интервала использовались бы знаки `<`:

```python
0 < score < 100
```

### 7.1. Проверка допустимого диапазона

```python
value = int(input("Значение от 0 до 100: "))

if 0 <= value <= 100:
    print("Допустимое значение")
else:
    print("Ошибка диапазона")
```

Отрицание того же диапазона:

```python
if value < 0 or value > 100:
    print("Ошибка диапазона")
```

Не следует писать:

```text
if value < 0 and value > 100:
```

Одно число не может одновременно быть меньше 0 и больше 100. Такое условие всегда ложно.

### 7.2. Точка в прямоугольнике

Пусть прямоугольник задан условиями:

```text
0 <= x <= 5
0 <= y <= 3
```

Точка принадлежит прямоугольнику, если выполняются оба ограничения:

```python
x = float(input("x: "))
y = float(input("y: "))

if 0 <= x <= 5 and 0 <= y <= 3:
    print("Внутри или на границе")
else:
    print("Снаружи")
```

Проверим несколько точек:

| Точка | Проверка x | Проверка y | Результат |
|---|---|---|---|
| `(2, 2)` | Истина | Истина | Внутри |
| `(5, 3)` | Истина | Истина | На границе, подходит |
| `(5.1, 3)` | Ложь | Истина | Снаружи |
| `(-1, 1)` | Ложь | Истина | Снаружи |

Граница включена, потому что используются `<=`.

### 7.3. Прямоугольник со строгой внутренней областью

Если граница не должна входить в область, условие меняется:

```python
if 0 < x < 5 and 0 < y < 3:
    print("Строго внутри")
```

Точка `(5, 3)` здесь уже не подходит. Один символ в сравнении меняет смысл задачи, поэтому граничные данные нужно проверять отдельно.

## 8. Минимум трёх чисел без min

В лабораторной работе нужно найти минимум, не используя готовую функцию `min()`, `max()` и сортировку. Цель задания - отработать изменение результата по условию.

Удобная схема: считать первое число текущим минимумом, затем сравнить с ним два остальных.

```python
a = int(input("a: "))
b = int(input("b: "))
c = int(input("c: "))

minimum = a

if b < minimum:
    minimum = b

if c < minimum:
    minimum = c

print(f"Минимум: {minimum}")
```

Для входа `2`, `10`, `3` трассировка выглядит так:

| Шаг | Проверка | minimum до | minimum после |
|---|---|---:|---:|
| Начало | Первое число принято за минимум | - | 2 |
| Число `b` | `10 < 2` ложно | 2 | 2 |
| Число `c` | `3 < 2` ложно | 2 | 2 |

Для входа `5`, `4`, `-1`:

| Шаг | Проверка | minimum до | minimum после |
|---|---|---:|---:|
| Начало | Первое число принято за минимум | - | 5 |
| Число `b` | `4 < 5` истинно | 5 | 4 |
| Число `c` | `-1 < 4` истинно | 4 | -1 |

Здесь нужны два независимых `if`. После изменения минимума на втором шаге третье число всё равно необходимо проверить.

### 8.1. Равные значения

При `5`, `5`, `5` обе проверки `<` ложны, и минимум остаётся равным первому числу. Ответ `5` правильный.

Можно использовать `<=`, но для самого числового результата это ничего не изменит. Строгое сравнение лучше показывает, что переменная обновляется только при нахождении меньшего значения.

### 8.2. Вариант с цепочкой ветвей

Задачу можно решить и через выбор одного числа:

```python
if a <= b and a <= c:
    minimum = a
elif b <= a and b <= c:
    minimum = b
else:
    minimum = c
```

Такая версия корректна, но содержит больше сравнений. Схема с текущим минимумом проще расширяется на поток из многих чисел и готовит к работе №4.

<a id="section-9"></a>

## 9. Калькулятор с выбором операции

Пользователь вводит два числа и один из символов `+`, `-`, `*`, `/`. Операции взаимоисключающие, поэтому подходит цепочка `if/elif/else`.

```python
first = float(input("Первое число: "))
second = float(input("Второе число: "))
operation = input("Операция: ")

if operation == "+":
    print(f"Результат: {first + second:.2f}")
elif operation == "-":
    print(f"Результат: {first - second:.2f}")
elif operation == "*":
    print(f"Результат: {first * second:.2f}")
elif operation == "/":
    if second == 0:
        print("Деление на ноль запрещено")
    else:
        print(f"Результат: {first / second:.2f}")
else:
    print("Неизвестная операция")
```

Проверка нулевого делителя находится внутри ветви деления. Для сложения или умножения значение второго числа может быть нулём.

### 9.1. Версия без вложенного if

Можно уточнить ветви:

```python
if operation == "+":
    result = first + second
elif operation == "-":
    result = first - second
elif operation == "*":
    result = first * second
elif operation == "/" and second != 0:
    result = first / second
elif operation == "/":
    print("Деление на ноль запрещено")
    result = None
else:
    print("Неизвестная операция")
    result = None

if result is not None:
    print(f"Результат: {result:.2f}")
```

`None` здесь обозначает отсутствие вычисленного результата. Последняя проверка не позволяет печатать число после ошибки.

Для первой версии `None` не требуется, и она проще для начального изучения. Вторая версия показывает, как отделить вычисление от общего вывода.

### 9.2. Почему нельзя использовать eval

Запись `eval(input())` пытается выполнить введённый текст как выражение Python. Она не ограничивает пользователя четырьмя операциями и может выполнить нежелательный код. Кроме того, `eval()` скрывает выбор ветви, ради которого дано задание.

В учебном калькуляторе каждую разрешённую операцию нужно обработать явно.

## 10. Составное правило: високосный год

Дополнительное задание работы №3 объединяет `and`, `or` и остаток от деления.

По григорианскому правилу год високосный, если выполняется хотя бы одно условие:

1. год делится на 400;
2. год делится на 4, но не делится на 100.

```python
year = int(input("Год: "))

is_leap = year % 400 == 0 or (
    year % 4 == 0 and year % 100 != 0
)

if is_leap:
    print("Високосный")
else:
    print("Не високосный")
```

Проверки:

| Год | Делится на 400 | Делится на 4 | Делится на 100 | Результат |
|---:|---|---|---|---|
| 1900 | Нет | Да | Да | Не високосный |
| 2000 | Да | Да | Да | Високосный |
| 2024 | Нет | Да | Нет | Високосный |
| 2023 | Нет | Нет | Нет | Не високосный |

Распространённая ошибка - проверять только делимость на 4. Тогда 1900 год ошибочно получится високосным.

## 11. Границы и таблица проверок

Условная программа может правильно работать на одном примере и ошибаться на границе. Поэтому проверка должна охватывать разные классы входных данных.

Для диапазона от 0 до 100:

| Класс | Значения |
|---|---|
| Ниже диапазона | `-1` |
| Нижняя граница | `0` |
| Внутри диапазона | Например, `37` |
| Верхняя граница | `100` |
| Выше диапазона | `101` |

Для порога 80 нужны как минимум значения `79`, `80`, `81`. Они показывают, с какой стороны включена граница.

### 11.1. Проверка категорий

Пусть заданы категории:

```text
0–19   Низкий
20–79  Средний
80–100 Высокий
```

Полезный набор:

```text
-1, 0, 19, 20, 79, 80, 100, 101
```

Каждая пара соседних значений проверяет переход между случаями.

### 11.2. Ожидаемый и фактический результат

Ожидаемый ответ вычисляют до запуска программы. Затем его сравнивают с фактическим выводом.

| Ввод | Ожидается | Фактически | Итог |
|---|---|---|---|
| `7`, `/`, `2` | `3.50` | Заполнить после запуска | Совпало / не совпало |
| `5`, `/`, `0` | Сообщение о запрете | Заполнить после запуска | Совпало / не совпало |
| `5`, `?`, `2` | Неизвестная операция | Заполнить после запуска | Совпало / не совпало |

Если сначала переписать ответ программы в колонку «ожидается», проверка перестанет быть независимой.

<a id="section-12"></a>

## 12. Переход от условия к циклу

Условие выполняет блок ноль или один раз. Цикл может выполнить блок много раз.

Сравним две схемы:

```python
if condition:
    action()
```

```python
while condition:
    action()
```

`if` проверяет условие один раз. `while` после выполнения тела возвращается к проверке. Если условие осталось истинным, начинается новая итерация.

**Итерация** - одно выполнение тела цикла.

Цикл нужен, когда действие повторяется по одному правилу:

- вывести числа диапазона;
- прочитать `n` значений;
- посчитать сумму потока;
- повторять ввод до подходящего числа;
- искать делитель до тех пор, пока он может существовать.

Копирование одной команды десять раз не заменяет цикл: при изменении количества повторов придётся менять структуру программы, а не только данные.

<a id="section-13"></a>

## 13. Цикл for

`for` последовательно получает значения из итерируемого объекта. В работе №4 таким объектом чаще всего будет диапазон `range`.

```python
for number in range(1, 5):
    print(number)
```

Результат:

```text
1
2
3
4
```

На первой итерации `number` равен 1, на второй - 2, затем 3 и 4. Значение 5 не входит в диапазон.

Схема:

```text
получить следующее значение
  ↓
присвоить его переменной цикла
  ↓
выполнить тело
  ↓
вернуться за следующим значением
```

Когда значения заканчиваются, выполнение продолжается после цикла.

### 13.1. Переменная цикла

Имя должно отражать смысл значения:

```python
for day in range(1, 8):
    print(f"День {day}")
```

Если номер итерации не используется, принято имя `_`:

```python
for _ in range(3):
    print("Повтор")
```

Подчёркивание остаётся обычным допустимым именем, но по соглашению показывает: значение намеренно не используется.

### 13.2. Команды после цикла

```python
for number in range(3):
    print(number)

print("Цикл завершён")
```

Результат:

```text
0
1
2
Цикл завершён
```

Последняя строка не имеет отступа, поэтому она не относится к телу цикла.

<a id="section-14"></a>

## 14. Функция range

Основные формы:

```python
range(stop)
range(start, stop)
range(start, stop, step)
```

| Запись | Значения |
|---|---|
| `range(5)` | `0, 1, 2, 3, 4` |
| `range(2, 6)` | `2, 3, 4, 5` |
| `range(2, 10, 2)` | `2, 4, 6, 8` |
| `range(10, 4, -2)` | `10, 8, 6` |
| `range(3, 3)` | Нет значений |

Правила:

- `start` входит в диапазон;
- `stop` не входит;
- `step` по умолчанию равен 1;
- шаг может быть отрицательным;
- шаг не может быть равен нулю.

### 14.1. Почему stop исключается

`range(n)` создаёт ровно `n` значений от 0 до `n - 1`. Это удобно для повторения заданного количества раз:

```python
n = int(input("Количество чисел: "))

for _ in range(n):
    number = int(input("Число: "))
    print(f"Получено: {number}")
```

Если `n = 3`, тело выполняется три раза. При `n = 0` не выполняется ни разу.

### 14.2. Направление диапазона

```python
range(5, 1)
```

Такой диапазон пуст, потому что стандартный шаг равен 1, а от 5 с положительным шагом нельзя приблизиться к исключаемой границе 1.

Для движения вниз нужен отрицательный шаг:

```python
range(5, 1, -1)
```

Значения: `5, 4, 3, 2`.

### 14.3. Нулевой шаг

```text
range(1, 5, 0)
```

Шаг 0 не изменяет значение, поэтому диапазон не может быть построен. Python выдаёт `ValueError`. Направление нужно выбирать как 1 или -1.

<a id="section-15"></a>

## 15. Диапазон в обе стороны

Задание требует вывести все числа от `a` до `b` включительно:

- по возрастанию при `a < b`;
- по убыванию при `a > b`;
- одно число при `a == b`.

Явное решение:

```python
a = int(input("a: "))
b = int(input("b: "))

if a < b:
    for number in range(a, b + 1):
        print(number)
elif a > b:
    for number in range(a, b - 1, -1):
        print(number)
else:
    print(a)
```

Здесь хорошо видны три случая. Можно сократить решение, вычислив шаг:

```python
a = int(input("a: "))
b = int(input("b: "))

if a <= b:
    step = 1
else:
    step = -1

for number in range(a, b + step, step):
    print(number)
```

Почему используется `b + step`:

| a | b | step | Вызов range | Значения |
|---:|---:|---:|---|---|
| 2 | 4 | 1 | `range(2, 5, 1)` | `2, 3, 4` |
| 4 | 2 | -1 | `range(4, 1, -1)` | `4, 3, 2` |
| 3 | 3 | 1 | `range(3, 4, 1)` | `3` |

Одна формула учитывает исключённую границу при обоих направлениях.

### 15.1. Типичные ошибки

```python
for number in range(a, b):
    print(number)
```

Проблемы:

- `b` не входит в вывод;
- при `a > b` диапазон пуст;
- при `a == b` не выводится даже одно число.

Исправление зависит не от добавления одного символа, а от полного требования задачи: включённая граница и два направления.

<a id="section-16"></a>

## 16. Счётчики и накопители

Цикл часто строит результат постепенно. Для этого значение создаётся до цикла и обновляется внутри.

**Накопитель суммы**:

```python
total = 0

for number in range(1, 5):
    total += number

print(total)  # 10
```

Запись `total += number` эквивалентна:

```python
total = total + number
```

Новое значение зависит от предыдущего.

**Счётчик**:

```python
positive_count = 0

for _ in range(4):
    number = int(input("Число: "))
    if number > 0:
        positive_count += 1

print(positive_count)
```

Счётчик изменяется только при выполнении условия.

### 16.1. Трассировка накопителя

Для суммы чисел 1, 2, 3, 4:

| Итерация | number | total до | total после |
|---:|---:|---:|---:|
| 1 | 1 | 0 | 1 |
| 2 | 2 | 1 | 3 |
| 3 | 3 | 3 | 6 |
| 4 | 4 | 6 | 10 |

Именно такую таблицу нужно уметь объяснить на защите работы №4.

### 16.2. Накопитель нельзя сбрасывать внутри цикла

Неверно:

```python
for _ in range(n):
    total = 0
    number = int(input())
    total += number
```

Перед каждой итерацией прежняя сумма теряется. После цикла останется только последнее число.

Правильно:

```python
total = 0

for _ in range(n):
    number = int(input())
    total += number
```

### 16.3. Количество и сумма по условию

```python
count = 0
total = 0

for _ in range(n):
    number = int(input())
    if number % 2 == 0:
        count += 1
        total += number
```

Если подходящих чисел нет, начальные нули остаются правильными результатами.

<a id="section-17"></a>

## 17. Статистика потока без списка

В работе №4 вводится `n >= 1`, затем ровно `n` целых чисел. Требуется найти:

- сумму;
- число положительных значений;
- максимум.

Список пока использовать не нужно. Каждое значение обрабатывается сразу после ввода.

```python
n = int(input("Количество: "))

first = int(input("Число: "))
total = first
positive_count = 1 if first > 0 else 0
maximum = first

for _ in range(n - 1):
    number = int(input("Число: "))
    total += number

    if number > 0:
        positive_count += 1

    if number > maximum:
        maximum = number

print(f"Сумма: {total}")
print(f"Положительных: {positive_count}")
print(f"Максимум: {maximum}")
```

Первое число обрабатывается отдельно, поэтому цикл читает ещё `n - 1` значение.

### 17.1. Инициализация суммы

Сумму можно начинать с нуля, потому что ноль не меняет сложение:

```python
total = 0
```

Число, которое не влияет на операцию, называют нейтральным элементом. Для сложения это ноль.

### 17.2. Инициализация максимума

Нельзя безусловно начинать максимум с нуля:

```python
maximum = 0  # Неверно для всех отрицательных чисел
```

Для входа `-5, -2, -8` программа оставит максимум равным нулю, хотя ноль не вводился.

Правильный текущий максимум должен происходить из потока. Поэтому первое значение читают отдельно:

```python
maximum = first
```

После этого каждое следующее число сравнивается с существующим кандидатом.

### 17.3. Проверка статистики

| Вход | Сумма | Положительных | Максимум |
|---|---:|---:|---:|
| `-5, -2, -8` | -15 | 0 | -2 |
| `0` | 0 | 0 | 0 |
| `3, -1, 7` | 9 | 2 | 7 |
| `5, 5, 5` | 15 | 3 | 5 |

Набор из одного числа проверяет начальные значения. Все отрицательные числа обнаруживают ошибку `maximum = 0`.

<a id="section-18"></a>

## 18. Альтернативная схема максимума

Можно выполнять цикл ровно `n` раз и назначить максимум при первой итерации:

```python
total = 0
positive_count = 0

for index in range(n):
    number = int(input("Число: "))
    total += number

    if number > 0:
        positive_count += 1

    if index == 0 or number > maximum:
        maximum = number
```

При `index == 0` правая часть `or` не вычисляется из-за короткого вычисления. Переменная `maximum` получает первое введённое число до того, как понадобится для сравнения.

Эта версия также корректна при `n >= 1`. Для начинающего отдельный ввод первого числа часто легче объяснить, потому что `maximum` всегда создан до цикла.

### 18.1. Инвариант цикла

После каждой обработанной части потока должны сохраняться утверждения:

- `total` равен сумме уже введённых чисел;
- `positive_count` равен количеству положительных среди них;
- `maximum` равен наибольшему среди них.

Такое утверждение называют **инвариантом цикла**. Оно помогает объяснить правильность алгоритма: если инвариант верен до очередного числа и обновления сохраняют его, то после последнего числа получен правильный результат.

<a id="section-19"></a>

## 19. Цикл while

`while` выполняет тело, пока условие истинно:

```python
count = 1

while count <= 3:
    print(count)
    count += 1
```

Результат:

```text
1
2
3
```

У цикла есть три важные части:

1. начальное состояние до цикла;
2. условие продолжения;
3. изменение состояния внутри тела.

Трассировка:

| Проверка | count перед телом | Вывод | count после тела |
|---|---:|---:|---:|
| `1 <= 3` | 1 | 1 | 2 |
| `2 <= 3` | 2 | 2 | 3 |
| `3 <= 3` | 3 | 3 | 4 |
| `4 <= 3` | 4 | - | Цикл завершён |

Условие проверяется перед каждой итерацией. Если оно ложно сразу, тело не выполняется ни разу.

### 19.1. Когда выбирать while

`while` подходит, если число повторов заранее неизвестно:

- повторять ввод до положительного числа;
- читать команды до слова `стоп`;
- искать делитель до заданной границы;
- выполнять процесс, пока сохраняется состояние.

Если нужно прочитать ровно `n` значений, `for _ in range(n)` обычно проще и яснее.

### 19.2. Условие продолжения и условие остановки

В задаче «повторять, пока число неположительное» условие цикла описывает продолжение:

```text
while number <= 0:
```

Цикл остановится, когда число станет положительным:

```text
number > 0
```

Эти условия противоположны. Полезно сформулировать оба словами до написания кода.

<a id="section-20"></a>

## 20. Повторный ввод

Требуется запрашивать целое число, пока пользователь не введёт положительное. Затем вывести квадрат и количество отклонённых попыток.

```python
number = int(input("Введите положительное число: "))
rejected = 0

while number <= 0:
    rejected += 1
    number = int(input("Повторите ввод: "))

print(f"Квадрат: {number ** 2}")
print(f"Отклонено попыток: {rejected}")
```

Для ввода `0`, `-2`, `3`:

| Введено | `number <= 0` | Действие | rejected |
|---:|---|---|---:|
| 0 | `True` | Отклонить и запросить снова | 1 |
| -2 | `True` | Отклонить и запросить снова | 2 |
| 3 | `False` | Выйти из цикла | 2 |

Квадрат равен 9, отклонено две попытки.

### 20.1. Почему первый ввод расположен до цикла

Условие `while number <= 0` нельзя проверить, пока переменная `number` не получила значение. Первый ввод создаёт начальное состояние.

Внутри цикла ввод повторяется, потому что состояние должно изменяться. Если убрать второй `input()`, неположительное число останется прежним и цикл не завершится.

### 20.2. Вариант с бесконечным циклом и break

```python
rejected = 0

while True:
    number = int(input("Введите положительное число: "))
    if number > 0:
        break
    rejected += 1
```

Эта версия корректна: `break` становится явным условием выхода. Однако для данного задания цикл `while number <= 0` лучше показывает условие продолжения и проще объясняется на защите.

<a id="section-21"></a>

## 21. Операторы break и continue

### 21.1. break

`break` немедленно завершает ближайший цикл:

```python
for number in range(1, 10):
    if number == 5:
        break
    print(number)
```

Результат:

```text
1
2
3
4
```

Число 5 уже присвоено переменной, но команда вывода после `break` не выполняется.

`break` полезен, если ответ найден и дальнейший перебор не нужен. Он завершает только тот цикл, внутри которого непосредственно находится.

### 21.2. continue

`continue` прекращает текущую итерацию и переходит к следующей:

```python
for number in range(-3, 4):
    if number == 0:
        continue
    print(f"10 / {number} = {10 / number:.2f}")
```

При нуле деление пропускается. Цикл продолжается со значением 1.

Тот же алгоритм можно записать без `continue`:

```python
for number in range(-3, 4):
    if number != 0:
        print(f"10 / {number} = {10 / number:.2f}")
```

Выбирайте запись, в которой основное действие легче увидеть. Частые `break` и `continue` могут скрыть путь выполнения.

### 21.3. Опасность continue в while

```text
number = 0

while number < 5:
    if number == 2:
        continue
    number += 1
```

При `number == 2` команда `number += 1` пропускается. Значение навсегда остаётся равным 2, и цикл зацикливается. В `while` нужно особенно внимательно проверять, достигается ли изменение состояния на каждом пути.

## 22. Проверка простого числа

Дополнительное задание работы №4 показывает совместную работу `while`, условия и `break`.

Целое `n >= 2` простое, если у него нет делителей от 2 до квадратного корня включительно.

```python
n = int(input("n >= 2: "))
divisor = 2
is_prime = True

while divisor * divisor <= n:
    if n % divisor == 0:
        is_prime = False
        break
    divisor += 1

if is_prime:
    print("Простое")
else:
    print("Составное")
```

Почему достаточно условия `divisor * divisor <= n`: если число имеет множитель больше квадратного корня, парный множитель будет меньше квадратного корня. Хотя бы один из них попадёт в проверяемый диапазон.

### 22.1. Трассировка для 17

| divisor | `divisor * divisor <= 17` | `17 % divisor == 0` | Действие |
|---:|---|---|---|
| 2 | `True` | `False` | Увеличить до 3 |
| 3 | `True` | `False` | Увеличить до 4 |
| 4 | `True` | `False` | Увеличить до 5 |
| 5 | `False` | - | Завершить цикл |

Делитель не найден, число простое.

### 22.2. Трассировка для 49

Проверяются 2, 3, 4, 5, 6 и 7. При `divisor = 7` остаток равен нулю, переменная `is_prime` становится ложной, затем `break` завершает цикл.

Контрольные значения:

| n | Результат |
|---:|---|
| 2 | Простое |
| 9 | Составное |
| 17 | Простое |
| 49 | Составное |

## 23. Условия внутри цикла

Индивидуальное задание работы №4 требует одним циклом найти количество и сумму значений, удовлетворяющих условию.

Общая схема:

```python
n = int(input("Количество: "))
count = 0
total = 0

for _ in range(n):
    number = int(input("Число: "))

    if условие_отбора:
        count += 1
        total += number

print(f"Количество: {count}")
print(f"Сумма: {total}")
```

Пример для чисел от 10 до 20 включительно:

```python
if 10 <= number <= 20:
```

## 24. for или while

Оба цикла способны решать многие одинаковые задачи, но обычно один вариант выражает намерение яснее.

| Ситуация | Предпочтительный цикл | Причина |
|---|---|---|
| Ввести ровно `n` чисел | `for` | Количество повторов известно |
| Вывести заданный диапазон | `for` | Есть последовательность `range` |
| Повторять до положительного ввода | `while` | Число попыток заранее неизвестно |
| Читать до команды `стоп` | `while` | Завершение зависит от значения |
| Искать делитель до границы | `while` или `for` | Оба варианта естественны |

Пример суммы через `while`:

```python
index = 0
total = 0

while index < n:
    number = int(input())
    total += number
    index += 1
```

Код работает, но требует вручную создавать и изменять `index`. При известном `n` цикл `for` короче и исключает ошибку с забытым `index += 1`:

```python
total = 0

for _ in range(n):
    number = int(input())
    total += number
```

## 25. Типичные ошибки

### 25.1. Условия

| Ошибка | Последствие | Проверка |
|---|---|---|
| `=` вместо `==` | `SyntaxError` | Прочитать строку `if` |
| Числа не преобразованы после `input()` | Сравнение строк | Проверить тип через `type()` |
| `and` вместо `or` вне диапазона | Ошибка никогда не обнаруживается | Ввести `-1` и `101` |
| `<` вместо `<=` | Теряется граница | Ввести значение точно на пороге |
| Общая ветвь стоит раньше частной | Частная ветвь недостижима | Проверить высокий порог |
| Несколько `if` вместо цепочки | Выполняются несколько категорий | Найти пересечение условий |
| `eval()` в калькуляторе | Выполняется произвольное выражение | Обработать операции явно |

### 25.2. Циклы

| Ошибка | Последствие | Проверка |
|---|---|---|
| `range(a, b)` для включённой границы | `b` пропускается | Проверить `a = 2`, `b = 4` |
| Положительный шаг при движении вниз | Цикл не выполняется | Проверить `a = 4`, `b = 2` |
| Накопитель создан внутри цикла | Старый результат теряется | Проследить две итерации |
| `maximum = 0` | Ошибка для отрицательного набора | Ввести `-5, -2, -8` |
| Счётчик увеличивается вне `if` | Считаются все значения | Ввести подходящее и неподходящее |
| Состояние `while` не изменяется | Бесконечный цикл | Найти изменение на каждом пути |
| `continue` пропускает изменение | Возможное зацикливание | Проверить путь до `continue` |

### 25.3. Ошибка на один шаг

Ошибки вида «на один меньше» или «на один больше» особенно характерны для диапазонов и счётчиков:

- забыто, что `stop` не входит в `range`;
- счётчик увеличен до проверки вместо после неё;
- отклонённая попытка подсчитана после успешного ввода;
- цикл выполнился `n - 1` или `n + 1` раз;
- граница интервала включена неправильным знаком.

Небольшая трассировочная таблица обычно быстрее обнаруживает такую ошибку, чем повторное чтение всего файла.

## 26. Трассировка и проверка завершения

Трассировка - пошаговая запись значений переменных. Она помогает понять, что программа действительно делает, а не что мы ожидаем от неё.

Для каждого цикла полезно ответить:

1. Какие значения созданы до первой итерации?
2. Как проверяется продолжение?
3. Какие переменные изменяются в теле?
4. Почему наступит завершение?
5. Какое утверждение верно после каждой итерации?

### 26.1. Пример трассировки отбора

Пусть нужно посчитать положительные чётные числа в наборе `-2, 0, 3, 10`.

| number | `number > 0` | `number % 2 == 0` | Подходит | count | total |
|---:|---|---|---|---:|---:|
| -2 | Ложь | Истина | Нет | 0 | 0 |
| 0 | Ложь | Истина | Нет | 0 | 0 |
| 3 | Истина | Ложь | Нет | 0 | 0 |
| 10 | Истина | Истина | Да | 1 | 10 |

Обе части `and` должны быть истинны.

### 26.2. Проверка завершения while

Для цикла:

```python
while number <= 0:
    number = int(input())
```

нельзя гарантировать, что пользователь обязательно введёт положительное число. Но можно объяснить условное завершение: как только будет введено значение больше нуля, условие станет ложным и цикл закончится.

Для цикла со счётчиком:

```python
count = 0
while count < 5:
    count += 1
```

завершение гарантировано алгоритмом: `count` начинается с нуля, на каждой итерации увеличивается на единицу и достигнет 5.

### 26.3. Остановка зациклившейся программы

В терминале работающую программу обычно можно прервать сочетанием Ctrl+C. В IDLE или другой среде используется команда остановки выполнения.

Принудительная остановка помогает вернуть управление, но не исправляет алгоритм. После неё нужно найти условие цикла и изменение переменных, от которых оно зависит.

## 28. Вопросы с разбором

### 28.1. Что напечатает цепочка?

```python
x = 10

if x > 0:
    print("A")
elif x > 5:
    print("B")
else:
    print("C")
```

Ответ: `A`. Первое условие истинно, после него остальные ветви цепочки пропускаются. Хотя `x > 5` тоже истинно, до этой проверки выполнение не дойдёт.

### 28.2. Что изменится с двумя if?

```python
x = 10

if x > 0:
    print("A")
if x > 5:
    print("B")
```

Ответ: будут напечатаны `A` и `B`. Конструкции независимы.

### 28.3. Почему условие диапазона неверно?

```python
if value < 0 and value > 100:
    print("Ошибка")
```

Одно число не может одновременно находиться ниже 0 и выше 100. Для выхода за диапазон нужна операция `or`.

### 28.4. Входит ли точка `(5, 3)` в прямоугольник?

При условиях `0 <= x <= 5` и `0 <= y <= 3` входит. Обе верхние границы включены знаком `<=`.

### 28.5. Почему `"10" < "2"` истинно?

Сравниваются строки. Первый символ `"1"` меньше `"2"`. Для числового сравнения нужны `int("10")` и `int("2")`.

### 28.6. Какие значения даёт range(2, 7, 2)?

`2, 4, 6`. Значение 7 не входит, а следующий шаг дал бы 8, которое уже прошло границу.

### 28.7. Сколько раз выполнится range(0)?

Ни разу. Диапазон пуст. Это удобно для случая `n = 0`, если результат должен остаться равным начальным значениям счётчика и суммы.

### 28.8. Какие значения даёт range(4, 1, -1)?

`4, 3, 2`. Граница 1 исключена.

### 28.9. Почему range(4, 1) пуст?

Шаг по умолчанию равен 1. С положительным шагом значение 4 удаляется от границы 1, поэтому последовательность не начинается.

### 28.10. Почему сумма начинается с нуля?

Ноль не меняет результат сложения. После обработки первого числа сумма становится равной этому числу.

### 28.11. Почему максимум нельзя всегда начинать с нуля?

В наборе из отрицательных чисел ноль окажется больше каждого элемента, хотя сам не входил в поток. Начальный максимум должен быть первым введённым значением.

### 28.12. Что произойдёт при continue в while до изменения счётчика?

Изменение может быть пропущено. Если условие продолжит оставаться истинным, программа зациклится.

### 28.13. Чем break отличается от continue?

`break` завершает цикл полностью. `continue` завершает только текущую итерацию и переходит к следующей.

### 28.14. Как проверить счётчик отклонённых попыток?

Использовать последовательности: сразу положительное число, одно неположительное перед положительным и несколько неположительных. Например, `3` даёт 0, а `0, -2, 3` даёт 2.

### 28.15. Почему ноль считается чётным?

Остаток `0 % 2` равен нулю, поэтому условие `number % 2 == 0` истинно.

### 28.16. Что даст статистика для одного нуля?

Сумма 0, положительных 0, максимум 0. Этот пример проверяет отдельную обработку первого значения.

### 28.17. Может ли while не выполниться ни разу?

Да. Условие проверяется до тела. Если первый введённый `number` уже положителен, цикл повторного ввода сразу пропускается.

### 28.18. Зачем рассчитывать ожидаемый ответ до запуска?

Так результат программы сравнивается с независимым прогнозом. Если считать ожидаемым любой фактический вывод, логическая ошибка останется незамеченной.

Основная идея лекции: условие выбирает путь, а цикл повторяет шаги. Правильная программа не только выдаёт ответ на одном примере, но и объяснимо работает на границах, равных значениях, нулях и отрицательных числах. Для этого до запуска формулируют случаи, для цикла определяют состояние и завершение, а результат проверяют независимыми данными.
